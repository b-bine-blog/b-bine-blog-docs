# 기능 명세 (Feature Specification): 소셜 로그인 (구글·카카오·네이버)

**기능 브랜치 (Feature Branch)**: `feature/social-login`

**작성일 (Created)**: 2026-10-13

**상태 (Status)**: Draft

**입력 (Input)**: 과제 항목 "OAuth2 소셜 로그인"(2026-10-13 사용자 요청). 사용자가 결정 카드에서 "구글+카카오"를 고른 뒤 "네이버 로그인도 만들어야 해"라고 더했다.

**근거**: 원래 요구사항분석서에는 소셜 로그인이 없다. 새 요구사항 USR-09(신설)로 두고, 결정은 D-125. 가입·로그인 규칙은 [001-member-auth](../001-member-auth/spec.md)를 그대로 따르고, 이 명세는 소셜 로그인 때문에 달라지는 것만 적는다.

## 확인 결과 (Clarifications)

### 세션 (Session) 2026-10-13

- Q: 같은 이메일로 이미 가입한 회원이 소셜로 시작하면 어떻게 하나? → A: 기존 비밀번호를 한 번 확인한 뒤 연결 (스토리 3, FR-005)
- Q: 카카오에서 이메일을 받지 못하면 어떻게 하나? → A: 처음 가입 때 이메일을 직접 입력하고 6자리 인증번호로 확인 (경계 상황, FR-016)

## 사용자 시나리오와 테스트 (User Scenarios & Testing) *(필수)*

### 사용자 스토리 1 - 소셜 계정으로 처음 가입 (우선순위: P1)

비회원이 로그인 창에서 "구글로 시작하기", "카카오로 시작하기", "네이버로 시작하기" 중 하나를 눌러 그 서비스에서 허락하면, 이메일 인증과 비밀번호 단계 없이 가입 ③단계(이름·닉네임·전화번호·필수 동의 2개)만 채우고 가입을 마친다.

**왜 이 우선순위인가**: 소셜 로그인의 핵심이다. 이것만 있어도 새 회원이 소셜 계정으로 들어올 수 있다.

**독립 테스트**: 가입된 적 없는 구글 계정으로 시작해 ③단계를 채우면 회원이 만들어지고 로그인 상태가 된다.

**인수 시나리오**:

1. **Given** 가입된 적 없는 구글 계정, **When** "구글로 시작하기"를 누르고 구글에서 허락하면, **Then** 가입 ③단계 화면이 열리고 이메일은 구글이 준 값으로 채워져 바꿀 수 없다.
2. **Given** ③단계 화면, **When** 이름·닉네임·전화번호를 규칙대로 쓰고 필수 동의 2개를 체크하면, **Then** 회원이 만들어지고 로그인 상태로 메인에 돌아간다.
3. **Given** ③단계 화면, **When** 끝내지 않고 30분이 지나면, **Then** 가입은 만들어지지 않고 다시 "구글로 시작하기"부터 해야 한다.
4. **Given** 구글에서 "취소"를 누름, **When** 사이트로 돌아오면, **Then** 로그인 창에 "소셜 로그인을 취소했어요"가 보이고 아무 계정도 만들어지지 않는다.

---

### 사용자 스토리 2 - 연결된 소셜 계정으로 로그인 (우선순위: P1)

소셜 계정이 연결된 회원은 버튼 한 번으로 로그인한다. "로그인 유지" 체크박스도 이메일 로그인과 똑같이 적용된다.

**독립 테스트**: 스토리 1로 가입한 회원이 로그아웃 뒤 "구글로 시작하기"를 누르면 ③단계 없이 바로 로그인된다.

**인수 시나리오**:

1. **Given** 구글이 연결된 회원, **When** "로그인 유지"를 체크하고 "구글로 시작하기"를 누르면, **Then** 바로 로그인되고 14일 동안 유지된다.
2. **Given** 같은 회원, **When** 체크하지 않고 로그인하면, **Then** 30분 무활동이면 로그아웃된다(001 FR-023).
3. **Given** 탈퇴한 회원의 소셜 계정, **When** 그 계정으로 시작하면, **Then** 예전 계정에 로그인되지 않고 새 가입(스토리 1)으로 간다.

---

### 사용자 스토리 3 - 이미 이메일로 가입한 회원 (우선순위: P1)

이메일로 가입한 회원이 같은 이메일의 소셜 계정으로 시작했을 때 계정이 둘로 나뉘지 않게 한다.

**인수 시나리오**:

1. **Given** `a@gmail.com`으로 이메일 가입한 회원, **When** 같은 이메일의 구글 계정으로 시작하면, **Then** "이미 가입된 이메일이에요. 비밀번호를 넣으면 구글을 연결해요" 창이 열리고 이메일은 가린 형태로 보인다.
2. **Given** 그 창, **When** 기존 비밀번호를 맞게 넣으면, **Then** 구글이 연결되고 로그인되며, 다음부터는 버튼만 누르면 로그인된다.
3. **Given** 그 창, **When** 비밀번호를 틀리면, **Then** 이메일 로그인 실패와 같이 실패 횟수가 늘고 3번부터 사람 확인, 5번이면 5분 잠금이 걸린다(001 FR-020~022).
4. **Given** 같은 이메일의 회원이 비밀번호 없이 다른 소셜(예: 카카오)로만 가입한 경우, **When** 구글로 시작하면, **Then** "카카오로 로그인한 뒤 내 정보에서 구글을 연결해 주세요"가 보이고 연결되지 않는다.

---

### 사용자 스토리 4 - 내 정보에서 연결 관리 (우선순위: P2)

회원은 내 정보 화면에서 구글·카카오·네이버 연결 상태를 보고 연결하거나 끊는다.

**인수 시나리오**:

1. **Given** 이메일로 가입한 회원, **When** 내 정보에서 "카카오 연결"을 누르고 허락하면, **Then** 다음부터 카카오로도 로그인된다.
2. **Given** 비밀번호가 없고 구글만 연결된 회원, **When** 구글 연결을 끊으려 하면, **Then** "로그인할 방법이 없어져요. 먼저 비밀번호를 만들어 주세요"가 보이고 끊기지 않는다.
3. **Given** 다른 회원에게 이미 연결된 카카오 계정, **When** 연결하려 하면, **Then** "이미 다른 계정에 연결된 카카오 계정이에요"가 보이고 연결되지 않는다.

### 경계 상황 (Edge Cases)

- 소셜 서비스가 이메일을 주지 않을 때(카카오는 비즈 앱이 아니면 이메일을 주지 않음): 처음 가입할 때만 이메일을 직접 입력받고, 회원가입 ①단계와 같은 6자리 인증번호(10분, 5번 틀리면 무효, 1분에 한 번 다시 보내기)로 확인한 뒤 ③단계로 간다. 인증한 이메일이 이미 가입된 회원의 것이면 FR-005(비밀번호 확인 뒤 연결)로 간다. 다음 로그인부터는 고유 번호로 찾으므로 이메일을 다시 묻지 않는다.
- 가입·연결을 마치기 전에 마무리 화면을 새로 고치거나 다시 들어오면 이어 하지 않는다. 로그인 화면으로 돌아가 "처음부터 다시 해 주세요"를 보여 주고, 소셜 버튼부터 다시 한다(2026-10-13 사용자 요청).
- 소셜 서비스가 "이메일 확인 안 됨"으로 주는 이메일은 믿지 않는다(구글 `email_verified=false` 등). 확인되지 않은 이메일은 받지 못한 것과 같게 처리한다.
- 로그인 도중 상태값(state)이 맞지 않거나, 10분 안에 돌아오지 않거나, 소셜 서비스가 오류를 주면 로그인 창에 "소셜 로그인에 실패했어요. 다시 시도해 주세요"를 보여준다.
- 소셜로 가입한 회원은 비밀번호가 없다. 이메일·비밀번호 로그인은 실패와 같은 문구로 거부하고(가입 방식을 알려주지 않음, D-28), "비밀번호 찾기"로 비밀번호를 만들 수 있다.
- 소셜 로그인에는 로그인 실패 횟수·잠금·사람 확인(001 FR-020~022)을 적용하지 않는다. 비밀번호를 쓰지 않기 때문이다. IP별 요청 제한(001 FR-021)은 적용한다.
- 비밀번호 변경·회원정보 수정 때의 "현재 비밀번호 확인"은 비밀번호가 없는 회원에게는 묻지 않는다. 비밀번호 변경 화면은 "비밀번호 만들기"로 보인다.
- 비밀번호가 없는 회원은 탈퇴할 때 비밀번호를 묻지 않는다. 로그인한 상태와 "정말 탈퇴할까요?" 확인만으로 탈퇴한다(001 FR-045의 비밀번호 확인은 비밀번호가 있는 회원에게만).
- 탈퇴하면 그 회원의 소셜 연결을 모두 지운다. 같은 소셜 계정으로 다시 가입할 수 있다(001 FR-047과 같음).
- 메인 관리자 계정은 소셜 로그인을 쓰지 않는다(SEC-09 관리자 분리).

## 요구사항 (Requirements) *(필수)*

### 기능 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 로그인 창과 가입 창에 "구글로 시작하기", "카카오로 시작하기", "네이버로 시작하기" 버튼을 두고, 각 서비스의 OAuth2 인가 코드 방식으로 로그인해야 한다. [USR-09]
- **FR-002**: 시스템은 소셜 서비스가 준 회원 고유 번호(구글 `sub`, 카카오 회원번호, 네이버 `id`)로 회원을 찾아야 하며, 이메일이나 이름으로 찾지 않아야 한다. 한 소셜 계정은 회원 한 명에게만 연결된다. [USR-09]
- **FR-003**: 시스템은 연결되지 않은 소셜 계정으로 시작하면 가입 ③단계(이름·닉네임·전화번호·필수 동의 2개, 001 FR-010~FR-016)를 받아 회원을 만들어야 한다. 이메일은 소셜 서비스가 확인한 값을 쓰고 화면에서 바꿀 수 없다. ①·②단계(이메일 인증번호, 비밀번호)는 없다. [USR-09, USR-01, 4.6]
- **FR-004**: 시스템은 소셜 서비스에서 돌아온 뒤 ③단계를 끝내야 하는 시간을 30분으로 두고(001 FR-007과 같음, 설정값), 그동안 소셜 계정 정보는 서버에만 두어야 한다. [USR-09, D-68]
- **FR-005**: 시스템은 소셜 서비스가 확인한 이메일과 같은 이메일의 회원이 이미 있으면 새 계정을 만들지 않고, 그 회원의 기존 비밀번호를 한 번 확인한 뒤에만 소셜 계정을 연결해야 한다. 비밀번호 확인에는 이메일 로그인과 같은 실패 횟수·사람 확인·잠금을 적용한다. 그 회원에게 비밀번호가 없으면 연결하지 않고 이미 연결된 소셜로 로그인한 뒤 내 정보에서 연결하라고 안내한다. 확인을 기다리는 동안 소셜 계정 정보는 서버에만 10분(설정값) 둔다. [USR-09, 6.5, SEC-03, D-68]
- **FR-006**: 시스템은 로그인 창의 "로그인 유지" 체크 상태를 소셜 로그인에도 적용하고, 로그인 뒤에는 이메일 로그인과 같은 로그인 쿠키(접근 자격 15분 + DB에 기록하는 연장 자격)를 발급해야 한다. [USR-03, SEC-04, D-53, D-61, D-82]
- **FR-007**: 시스템은 소셜 로그인 요청마다 예측할 수 없는 state 값을 만들어 돌아올 때 확인하고, 10분(설정값) 안에 돌아온 한 번만 받아야 한다. PKCE를 지원하는 서비스는 PKCE도 쓴다. [SEC-10, USR-09]
- **FR-008**: 시스템은 소셜 서비스의 접근 토큰을 회원 정보를 받는 데만 쓰고 저장하지 않아야 한다. [USR-09, 4.6]
- **FR-009**: 시스템은 소셜로 가입한 회원의 비밀번호를 비워 두고, 그 회원의 이메일·비밀번호 로그인은 일반 실패와 같은 문구로 거부해야 한다. "비밀번호 찾기"(001 FR-030~FR-033)로 비밀번호를 만들면 이메일 로그인도 된다. [USR-06, D-28]
- **FR-010**: 시스템은 내 정보 화면에서 구글·카카오·네이버 연결 상태를 보여주고 연결·끊기를 하게 해야 한다. 끊으면 로그인할 방법(비밀번호나 다른 소셜 연결)이 하나도 남지 않을 때는 끊지 않아야 한다. [USR-07, USR-09]
- **FR-011**: 시스템은 다른 회원에게 연결된 소셜 계정을 연결하지 않아야 한다. [USR-09]
- **FR-012**: 시스템은 회원이 탈퇴하면 그 회원의 소셜 연결을 바로 지워야 한다. [USR-05, 4.5]
- **FR-013**: 시스템은 소셜 로그인에도 IP별 요청 제한(같은 IP 10분 20번, 001 FR-021)을 적용하고, 계정 잠금과 사람 확인은 적용하지 않아야 한다. [SEC-03, D-80]
- **FR-014**: 시스템은 소셜 서비스의 앱 키(Client ID·Secret)와 돌아올 주소를 코드에 넣지 않고 설정값(환경 변수)으로 받아야 하며, 키가 비어 있으면 그 서비스 버튼을 숨겨야 한다. [D-68]
- **FR-015**: 시스템은 소셜 서비스에서 받은 정보 중 이메일과 고유 번호만 저장하고, 이름·프로필 사진 등은 저장하지 않아야 한다(4.6 수집 항목을 늘리지 않음). [4.6, D-41]
- **FR-016**: 시스템은 소셜 서비스가 확인된 이메일을 주지 않으면 처음 가입할 때만 이메일을 입력받아 6자리 인증번호로 확인해야 한다. 인증번호 규칙은 가입 인증(001 FR-003~FR-005)과 같다. 인증한 이메일이 이미 가입된 회원의 것이면 FR-005로 간다. [USR-09, USR-02, D-10, D-69]

### 핵심 엔티티 (Key Entities)

- **소셜 연결**: 회원 한 명과 소셜 계정 하나의 연결. 서비스(GOOGLE·KAKAO·NAVER), 그 서비스의 회원 고유 번호, 연결할 때의 이메일, 연결한 시각. (서비스, 고유 번호)는 중복 불가. 탈퇴하면 삭제.
- **회원 계정**(001): 비밀번호 해시를 비울 수 있게 바뀐다. 비밀번호가 없으면 이메일 로그인을 할 수 없다.
- **소셜 가입 대기**: 소셜 서비스에서 돌아왔지만 ③단계를 끝내지 않은 상태. 서비스, 고유 번호, 확인된 이메일(없으면 FR-016으로 인증한 뒤 채움), 만료 시각(30분). 끝나거나 만료되면 삭제.

## 성공 기준 (Success Criteria) *(필수)*

### 측정 가능한 결과 (Measurable Outcomes)

- **SC-001**: 처음 온 사람이 소셜 버튼을 누르고 ③단계를 채워 가입을 마치기까지 1분 안에 끝난다(이메일 가입보다 단계가 2개 적다).
- **SC-002**: 연결된 회원이 소셜 버튼을 누른 뒤 추가 입력 없이 로그인된 비율이 100%다.
- **SC-003**: 같은 소셜 계정으로 동시에 가입을 끝내도 회원이 2명 이상 생긴 경우가 0건이다.
- **SC-004**: state가 없거나 틀리거나 10분이 지난 요청, 한 번 쓴 state를 다시 쓴 요청으로 로그인된 경우가 0건이다.
- **SC-005**: 서버 응답과 DB 어디에도 소셜 서비스의 접근 토큰이 남은 경우가 0건이다.
- **SC-006**: 로그인할 방법이 하나도 없는 회원이 생긴 경우가 0건이다.

## 가정 (Assumptions)

- 구글·카카오·네이버 개발자 화면의 앱 등록과 키 발급, GitHub secrets 등록은 사용자가 직접 한다. 돌아올 주소는 `https://mainttblog.java21.net/login/oauth2/code/{google|kakao|naver}`이고, 내 컴퓨터 실행용으로 `http://localhost:8080/...`도 등록한다.
- 구글은 확인된 이메일(`email_verified=true`)을 준다고 본다. 네이버는 이메일 제공 동의를 필수로 설정하면 이메일을 준다. 네이버는 개발 중 상태에서는 등록한 테스트 아이디만 로그인되고, 모든 사람이 쓰려면 네이버의 서비스 검수를 받아야 한다(사용자가 신청).
- 소셜 로그인 뒤 사이트의 로그인 쿠키는 기존 JWT 방식을 그대로 쓴다. 서버 세션을 새로 쓰지 않는다(D-53).
- 애플·깃허브 등 다른 서비스는 범위 밖이다.
- 소셜 서비스에서 받은 프로필 사진·이름을 가져와 채우는 기능은 범위 밖이다(FR-015).
