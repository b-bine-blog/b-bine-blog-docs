# 기능 명세 (Feature Specification): 블로그 채팅과 챗봇

**기능 브랜치 (Feature Branch)**: `feature/blog-chat`

**작성일 (Created)**: 2026-10-14

**상태 (Status)**: Draft

**입력 (Input)**: "개인 블로그에서 챗봇 기능을 넣고 싶은데 어디까지 적용할지 미리 정하고 가야 할 것 같아"(2026-10-14 사용자). 같은 날 사용자가 정한 것: 폴링 방식, 3초마다 확인, 범위는 2단계(명령어 봇 + 관리 봇). AI 답변 봇(3단계)은 이번 범위가 아니다.

**근거**: 원래 요구사항분석서에는 채팅이 없다. 새 요구사항 SOC-07(신설)로 두고, 전달 방식 결정은 D-131. 블로그별 역할은 [002-blog-management](../002-blog-management/spec.md), 신고·차단은 [003-social-notification](../003-social-notification/spec.md)을 따른다.

## 사용자 시나리오와 테스트 (User Scenarios & Testing) *(필수)*

### 사용자 스토리 1 - 블로그 채팅창에서 대화 (우선순위: P1)

블로그를 보는 사람이 블로그 화면 옆 채팅창을 열어 메시지를 보내고, 다른 사람의 메시지를 3초 안에 본다.

**왜 이 우선순위인가**: 채팅창이 있어야 봇도 동작한다. 이것만으로도 블로그 방문자끼리 대화할 수 있다.

**독립 테스트**: 두 브라우저로 같은 블로그 채팅창을 열고 한쪽에서 보내면 다른 쪽에 3초 안에 보인다.

**인수 시나리오**:

1. **Given** 채팅을 켠 공개 블로그, **When** 회원이 채팅창에 "안녕하세요"를 보내면, **Then** 내 화면에는 바로, 같은 채팅창을 연 다른 사람 화면에는 3초 안에 닉네임과 함께 보인다.
2. **Given** 채팅창을 처음 열 때, **Then** 최근 메시지 50개가 보이고 위로 올리면 더 이전 메시지를 불러온다.
3. **Given** 채팅을 끈 블로그, **Then** 채팅창 버튼이 보이지 않는다.
4. **Given** 비공개 블로그, **When** 멤버가 아닌 회원이 채팅 주소를 직접 부르면, **Then** 블로그 글과 같이 볼 수 없다(404).
5. **Given** 내가 차단한 회원의 메시지, **Then** 내 화면에는 보이지 않는다(003 차단 규칙).

---

### 사용자 스토리 2 - 명령어 봇 (우선순위: P1)

블로그장이 `!공지`, `!소개` 같은 명령어와 답을 등록하면, 방문자가 채팅에 명령어를 쳤을 때 봇이 답을 올린다.

**독립 테스트**: 블로그 관리 화면에서 `!소개` → "여행 기록 블로그예요"를 등록하고 채팅에 `!소개`를 치면 봇 이름으로 답이 올라온다.

**인수 시나리오**:

1. **Given** `!소개`가 등록된 블로그, **When** 누가 채팅에 `!소개`를 보내면, **Then** 그 메시지 바로 뒤에 봇이 "여행 기록 블로그예요"를 올리고 모두에게 보인다.
2. **Given** 등록되지 않은 `!없는말`, **When** 보내면, **Then** 일반 메시지로 올라가고 봇은 답하지 않는다.
3. **Given** `!명령어`, **When** 누가 보내면, **Then** 봇이 등록된 명령어 목록을 답한다(기본 명령어, 지울 수 없음).
4. **Given** 블로그 관리 화면, **When** 블로그장이 명령어를 더하거나 고치거나 지우면, **Then** 다음 명령어부터 바로 반영된다.
5. **Given** 같은 사람이 같은 명령어를 10초 안에 다시 치면, **Then** 봇은 다시 답하지 않는다(도배 방지).

---

### 사용자 스토리 3 - 관리 봇 (우선순위: P1)

봇이 금칙어와 도배를 막고, 새 글이 올라오면 채팅에 알린다.

**인수 시나리오**:

1. **Given** 블로그장이 금칙어 "광고"를 등록한 블로그, **When** 누가 "광고 받아요"를 보내면, **Then** [NEEDS CLARIFICATION: 금칙어가 들어간 메시지를 어떻게 하나? 보내지 않고 막기 / 올리되 가려서 보이기]
2. **Given** 한 사람이 짧은 시간에 메시지를 많이 보내면(기본 10초에 5개), **Then** [NEEDS CLARIFICATION: 도배한 사람을 어떻게 하나? 잠깐(기본 1분) 채팅 금지 / 경고 메시지만 / 블로그 제재와 연결]
3. **Given** 채팅을 켠 블로그, **When** 멤버가 새 글을 올리면, **Then** 봇이 "새 글: {제목}"을 링크와 함께 채팅에 올린다. 블로그장이 관리 화면에서 끌 수 있다.
4. **Given** 블로그장·부블로그장, **When** 채팅의 메시지를 지우면, **Then** 모두의 화면에서 "지운 메시지예요"로 바뀐다.

---

### 사용자 스토리 4 - 채팅 설정 (우선순위: P2)

블로그장은 관리 화면에서 채팅을 켜고 끄고, 명령어·금칙어·새 글 알림을 관리한다.

**인수 시나리오**:

1. **Given** 새로 만든 블로그, **Then** 채팅은 꺼져 있다. 블로그장이 켜야 채팅창이 보인다.
2. **Given** 부블로그장, **When** 블로그장이 "채팅 관리" 권한을 체크해 주면(D-71), **Then** 부블로그장도 채팅 설정·메시지 삭제를 할 수 있다.
3. **Given** 일반 멤버나 다른 블로그의 블로그장, **When** 채팅 설정 API를 부르면, **Then** 거절된다(403, SEC-07).

### 경계 상황 (Edge Cases)

- 채팅창을 닫거나 다른 탭으로 가면 확인을 멈추고, 돌아오면 놓친 메시지를 한 번에 받는다.
- 3초마다 확인하는 요청은 로그인 연장(30분 무활동)에 넣지 않는다(D-72와 같음).
- 앱 2개(8370·8371) 중 어느 쪽에 요청이 가도 같은 메시지를 본다. 메시지·도배 횟수는 DB에 둔다(원칙 IV).
- 메시지는 글자 그대로 보여 준다(textContent). 링크는 봇의 새 글 알림만 누를 수 있다(SEC-06, D-64).
- 탈퇴한 회원의 메시지는 "탈퇴한 회원"으로 보인다.
- 블로그가 폐쇄되면 채팅도 함께 닫히고 메시지는 블로그 데이터와 같이 지운다(4.5).
- 정지·강퇴된 사람(BLG-13)은 그 블로그 채팅에 보낼 수 없다.

## 요구사항 (Requirements) *(필수)*

### 기능 요구사항 (Functional Requirements)

- **FR-001**: 블로그마다 채팅방이 하나 있고, 블로그장이 켜고 끈다. 새 블로그는 꺼진 상태다. [SOC-07]
- **FR-002**: 채팅을 볼 수 있는 사람은 그 블로그 글을 볼 수 있는 사람과 같다(공개·일부 공개·비공개, BLG). [SOC-07, SEC-07]
- **FR-003**: [NEEDS CLARIFICATION: 비회원도 채팅에 메시지를 보낼 수 있나? 회원만 보내기(비회원은 읽기만) / 비회원도 보내기]
- **FR-004**: 화면은 3초마다 마지막으로 받은 메시지 뒤의 새 메시지를 묻는다(폴링, D-131). 간격은 설정값 `chat.poll-interval`(기본 3초)이다. [D-131, D-68]
- **FR-005**: 메시지는 1~200자, 글자 그대로 보여 준다. [SOC-07, SEC-06]
- **FR-006**: 처음 열 때 최근 50개, 위로 올리면 50개씩 더 불러온다. [SOC-07]
- **FR-007**: 메시지는 보낸 지 30일이 지나면 매일 04:00 정리 작업에서 지운다. 기간은 설정값 `chat.retention-days`(기본 30일)이다. [SOC-07, 4.5, D-68]
- **FR-008**: 명령어는 `!`로 시작하고, 블로그마다 최대 30개, 답은 최대 300자다. `!명령어`는 기본 명령어로 목록을 답한다. [SOC-07]
- **FR-009**: 같은 사람이 같은 명령어를 10초 안에 다시 치면 봇은 답하지 않는다. [SOC-07]
- **FR-010**: 금칙어는 블로그마다 최대 100개, 대소문자·띄어쓰기를 무시하고 찾는다. 위반 때 처리는 스토리 3-1을 따른다. [SOC-07]
- **FR-011**: 도배 기준(기본 10초에 5개)과 조치는 스토리 3-2를 따르고 숫자는 설정값이다. [SOC-07, D-68]
- **FR-012**: 새 글 알림은 기본으로 켜져 있고, 공개 범위가 맞는 글만 알린다. [SOC-07, BRD]
- **FR-013**: 블로그장과 "채팅 관리" 권한이 있는 부블로그장만 설정을 바꾸고 메시지를 지운다. 서버가 매 요청마다 역할을 확인한다. [SEC-07, D-71]
- **FR-014**: 메시지는 신고할 수 있고 신고는 블로그장에게 간다(003 신고 규칙). [SOC-03]
- **FR-015**: 봇 메시지는 "봇" 표시로 사람 메시지와 구별된다. [SOC-07]

### 핵심 데이터 (Key Entities)

- **채팅 설정**: 블로그별 켜짐 여부, 새 글 알림 켜짐 여부
- **채팅 메시지**: 블로그, 보낸 사람(또는 봇), 내용, 보낸 시각, 지움 여부
- **명령어**: 블로그, 명령어, 답
- **금칙어**: 블로그, 단어
- **채팅 금지(도배)**: 블로그, 회원, 끝나는 시각

## 성공 기준 (Success Criteria) *(필수)*

### 측정 가능한 결과 (Measurable Outcomes)

- **SC-001**: 보낸 메시지가 같은 채팅창을 연 다른 사람에게 3초(확인 간격) + 1초 안에 보인다.
- **SC-002**: 등록된 명령어를 치면 다음 확인 때 봇 답이 함께 보인다.
- **SC-003**: 앱 2개 중 하나를 바꾸는 롤링 배포 중에도 채팅이 끊기지 않고 메시지가 사라지지 않는다.
- **SC-004**: 채팅창 100개가 3초마다 확인해도 메인·목록 응답 목표(1~2초, 4.2)를 지킨다.

## 가정 (Assumptions)

- 채팅창은 블로그 화면 오른쪽 아래 버튼으로 열고 닫는다. 휴대폰에서는 화면 전체로 연다.
- 관리자(메인 관리자)는 블로그 활동을 하지 않으므로 채팅에 보내지 않는다(D-90).
- AI 답변 봇(3단계)은 이번 범위가 아니다. 나중에 붙일 수 있게 봇 답을 만드는 부분은 따로 둔다.
- 보관 기간 30일은 삭제 데이터 30일 보관 원칙(4.5)에 맞춘 추천값이다.
- 숫자(200자, 50개, 30개, 300자, 100개, 10초, 10초에 5개, 1분)는 모두 설정값이고 추천값이다.
