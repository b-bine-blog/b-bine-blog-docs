## 사용자 시나리오와 테스트 (User Scenarios & Testing) *(필수)*

### 사용자 스토리 1 - 글 쓰기·읽기·수정·삭제 (우선순위: P1)

블로그 멤버(블로그장 포함)가 참여한 블로그에 제목과 본문으로 글을 쓴다. 본문은 마크다운으로 쓰고, 읽는 사람에게는 위험한 내용이 걸러진 화면으로 보인다. 수정은 작성자 본인만, 삭제는 작성자 본인, 그 블로그의 블로그장, 메인 관리자가 할 수 있다.

**이 우선순위인 이유**: 글이 있어야 목록·검색·피드·댓글·공유가 의미가 있다. 게시판의 가장 기본 기능이고 우선순위 "상"이다(BRD-01).

**독립 테스트**: 멤버 계정으로 글 하나를 쓰고, 비회원으로 그 글을 열어 보고, 작성자·블로그장·다른 멤버·메인 관리자 계정으로 수정·삭제를 각각 시도하면 된다. 다른 기능 없이도 글을 쓰고 읽는 가치가 생긴다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 블로그 A의 멤버가 로그인했을 때, **When** 제목 "첫 글"(1~30자)과 본문(5,000자 이하)으로 글을 쓰면, **Then** 글이 저장되고 블로그 A에 작성자 닉네임과 함께 보인다.
2. **Given** 글쓰기 화면에서, **When** 제목을 비우거나 31자로 넣으면, **Then** "제목은 1~30자" 규칙 위반으로 저장되지 않는다.
3. **Given** 글쓰기 화면에서, **When** 공백·마크다운 기호를 포함해 본문을 5,001자로 넣으면, **Then** "본문은 최대 5,000자" 규칙 위반으로 저장되지 않는다. **And** 화면을 거치지 않고 직접 보낸 요청도 서버가 글자 수를 검사해 거부한다(D-92).
4. **Given** 블로그 A의 멤버가 아닌 회원과 비회원이, **When** 블로그 A에 글쓰기를 요청하면, **Then** 거부된다.
5. **Given** 본문에 `<script>` 태그나 `onerror` 같은 위험한 속성을 넣은 글이 있을 때, **When** 누군가 그 글을 열면, **Then** 위험한 부분은 제거된 채 표시되고 스크립트는 실행되지 않는다.
6. **Given** 제목이나 닉네임에 `<b>굵게</b>` 같은 HTML이 들어 있을 때, **When** 화면에 표시되면, **Then** 태그로 해석되지 않고 글자 그대로 보인다.
7. **Given** 멤버 갑이 쓴 글이 있을 때, **When** 갑이 수정하면, **Then** 수정된다. **When** 그 블로그의 블로그장이나 메인 관리자가 수정을 요청하면, **Then** 거부된다.
8. **Given** 멤버 갑이 쓴 글이 있을 때, **When** 같은 블로그의 멤버 을이 삭제를 요청하면, **Then** 거부된다.
9. **Given** 블로그 A의 블로그장이, **When** 블로그 A에 있는 멤버 갑의 글을 삭제하면, **Then** 삭제되고 갑에게 "내 글 삭제됨" 알림이 간다. **When** 블로그 B의 글을 삭제하려 하면, **Then** 거부된다.
10. **Given** 메인 관리자가, **When** 어느 블로그의 글이든 삭제하면, **Then** 삭제되고 작성자에게 "내 글 삭제됨" 알림이 간다.
11. **Given** 글의 삭제 버튼을 누르면, **When** 확인 창 "글을 정말 삭제하시겠습니까"가 뜨고 취소를 누르면, **Then** 글은 그대로 남는다.
12. **Given** 글이 삭제된 뒤, **When** 누구든 그 글을 열거나 목록·검색·피드를 보면, **Then** 30일 동안 보이지 않고, 30일 뒤에는 글·댓글·사진이 완전히 삭제된다.
13. **Given** 글쓰기 중에 브라우저가 실수로 닫혔을 때, **When** 같은 브라우저에서 다시 글쓰기 화면을 열면, **Then** 자동 저장된 내용이 남아 있다. 다른 기기에서는 이어서 쓸 수 없다(1차는 브라우저에만 저장).
14. **Given** 폐쇄 예정(7일 유예) 중인 블로그의 멤버가, **When** 글을 쓰면, **Then** 평소처럼 저장된다.
15. **Given** 메인 관리자 계정으로 로그인했을 때, **When** 어느 블로그에든 글쓰기를 요청하면, **Then** 거부된다. 메인 관리자의 글쓰기는 메인 공지(BRD-10)만 된다(D-90).

### 사용자 스토리 2 - 글 목록·페이징·카테고리 (우선순위: P1)

방문자가 블로그와 메인의 글 목록을 최신순으로 보고, 한 페이지 개수(10·20·30개)를 골라 번호 페이지로 넘긴다. 블로그 안에서는 카테고리별로 글을 본다.

**이 우선순위인 이유**: 글을 찾아 읽는 기본 경로이고 우선순위 "상"이다(BRD-02). 성능 목표(1~2초)가 직접 걸리는 화면이다(4.2).

**독립 테스트**: 글 35개가 있는 블로그에서 개수를 10·20·30개로 바꾸며 페이지 수와 순서를 확인하고, 카테고리 두 개에 나눠 넣은 글이 카테고리별로 나뉘어 보이는지 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 글이 35개 있는 공개 블로그에, **When** 비회원이 처음 목록을 열면, **Then** 최신 글부터 10개가 보이고(기본값 10개) 번호 페이지 1~4가 보인다.
2. **Given** 같은 목록에서, **When** 한 페이지 개수를 20개로 고르면, **Then** 20개씩 2페이지로, 30개로 고르면 30개씩 2페이지로 나뉜다.
3. **Given** 같은 목록에서, **When** 10·20·30이 아닌 개수(예: 50)를 요청하면, **Then** 그 개수로 보여주지 않는다.
4. **Given** 번호 페이지가 있을 때, **When** 3페이지 번호를 누르면, **Then** 앞 페이지를 거치지 않고 바로 3페이지로 간다.
5. **Given** 글에 이미지가 있을 때, **When** 목록에서 그 글 제목 위에 마우스 포인터를 올리면, **Then** 그 글의 사진이 줄여서 보인다.
6. **Given** 블로그장이 "여행", "맛집" 카테고리를 만들어 두었을 때, **When** 멤버가 글을 "여행"으로 분류해 쓰고 방문자가 "여행" 카테고리를 누르면, **Then** "여행" 글만 보인다.
7. **Given** 글 관리 권한이 없는 일반 멤버가, **When** 카테고리 추가·수정·삭제를 요청하면, **Then** 거부된다(카테고리 관리는 블로그장 또는 글 관리 권한을 받은 부블로그장).
8. **Given** 블로그를 떠난 멤버의 글이 있을 때, **When** 목록을 보면, **Then** 작성자가 "탈퇴한 계정"으로 보인다. **Given** 회원탈퇴한 회원의 글이면, **Then** 작성자가 "탈퇴한 회원"으로 보인다.

### 사용자 스토리 3 - 메인 피드 (우선순위: P1)

방문자가 메인에서 전체 블로그의 최신·인기 공개 글을 본다. 인기 글은 좋아요 수가 많은 순이고, 같으면 최신순이다(D-89). 로그인한 회원은 팔로우한 회원의 새 글과 구독한 블로그의 새 글을 각각 다른 탭에서 본다.

**이 우선순위인 이유**: 메인 화면의 핵심이고 우선순위 "상"이다(BRD-09). 팔로우·구독(SOC-01)이 쓸모 있게 되는 화면이다.

**독립 테스트**: 공개 블로그·일부 공개 블로그·비공개 블로그에 글을 하나씩 쓰고, 회원 하나를 팔로우하고 블로그 하나를 구독한 계정으로 각 탭에 무엇이 보이는지 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 공개·일부 공개·비공개 블로그에 각각 새 글이 있을 때, **When** 비회원이 메인 피드의 최신 글을 보면, **Then** 공개 블로그의 글만 보인다.
2. **Given** 회원이 갑을 팔로우하고 블로그 B를 구독했을 때, **When** 팔로우 탭을 열면, **Then** 갑의 새 글이 보이고, **When** 구독 탭을 열면, **Then** 블로그 B의 새 글이 보인다. 두 글이 한 목록에 섞이지 않는다.
3. **Given** 갑이 블로그 B에 쓴 글이 있고 회원이 갑을 팔로우하면서 블로그 B도 구독할 때, **When** 두 탭을 보면, **Then** 그 글은 팔로우 탭과 구독 탭에 각각 보인다.
4. **Given** 피드에 보이던 글이, **When** 삭제되거나, 작성자를 차단하거나, 그 블로그가 비공개로 바뀐 직후 피드를 다시 열면, **Then** 그 글은 바로 보이지 않는다(멤버가 아닌 구독자 기준).
5. **Given** 블로그 B가 비공개로 바뀌었고 회원이 B의 구독자이지만 멤버가 아닐 때, **When** 구독 탭을 열면, **Then** B의 글이 보이지 않는다. 구독은 그대로 남는다.
6. **Given** 비회원이, **When** 팔로우 탭이나 구독 탭을 열려고 하면, **Then** 볼 수 없다(팔로우·구독은 회원 기능).
7. **Given** 좋아요가 각각 8개, 3개, 3개인 공개 글 P, Q, R이 있고 R이 Q보다 나중에 쓰였을 때, **When** 메인 피드의 인기 글을 보면, **Then** P, R, Q 순서로 보인다(좋아요 수가 많은 순, 같으면 최신순, D-89).

### 사용자 스토리 4 - 이미지 첨부 (우선순위: P2)

멤버가 글에 사진을 올린다. 허용한 형식·크기·개수만 받고, 실행 파일이나 위장 파일은 막으며, 사진 속 위치 정보는 지운다.

**이 우선순위인 이유**: 블로그 글에 사진은 자주 쓰이지만 글 없이 의미가 없고 우선순위 "중"이다(BRD-05). 보안 요구(SEC-08)가 걸려 있어 따로 검증해야 한다.

**독립 테스트**: 형식·크기·개수 경계값 파일과 확장자를 바꾼 실행 파일, GPS 정보가 든 사진을 올려 결과를 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 글쓰기 화면에서, **When** 2.9MB짜리 jpg·jpeg·png·gif·webp 사진을 올리면, **Then** 올라가고 본문에 들어간다.
2. **Given** 글쓰기 화면에서, **When** 3MB를 넘는 사진을 올리면, **Then** "장당 3MB" 제한으로 막힌다.
3. **Given** 글쓰기 화면에서, **When** svg, 동영상, pdf·hwp 같은 문서, zip 같은 압축 파일을 올리면, **Then** 막힌다.
4. **Given** 실행 파일의 확장자만 `.jpg`로 바꾼 파일을, **When** 올리면, **Then** 파일 형식과 파일 앞부분 내용이 사진이 아니라서 막힌다.
5. **Given** 사진 10장이 들어간 글에, **When** 11번째 사진을 올리면, **Then** "글 하나에 최대 10장" 제한으로 막힌다.
6. **Given** 한 번에 여러 장을 보낼 때, **When** 보내는 전체 용량이 10MB를 넘으면, **Then** 막힌다.
7. **Given** GPS 위치가 들어 있는 휴대폰 사진을, **When** 올린 뒤 그 사진 파일을 내려받아 보면, **Then** 위치 정보(EXIF)가 남아 있지 않다.
8. **Given** 원래 이름이 `../../etc/passwd.jpg`인 사진을, **When** 올리면, **Then** 서버에는 무작위 고유 이름으로 저장되어 다른 경로나 다른 파일을 덮어쓰지 않는다.

### 사용자 스토리 5 - 댓글·대댓글·좋아요 (우선순위: P2)

회원이 글에 댓글과 1단계 대댓글을 달고, 글에 좋아요를 누른다. 글 작성자와 댓글 작성자는 알림을 받는다.

**이 우선순위인 이유**: 블로그 안의 소통 기능이고 우선순위 "중"이다(BRD-06). 글 기능 위에 얹혀 따로 검증할 수 있다.

**독립 테스트**: 공개 글 하나에 회원 둘이 댓글·대댓글·좋아요를 남기고, 알림과 표시(@닉네임, "수정됨", "삭제된 댓글입니다")를 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 공개 블로그의 글에, **When** 로그인한 회원이 1~500자 댓글을 달면, **Then** 댓글이 보이고 글 작성자에게 "내 글에 댓글" 알림이 간다.
2. **Given** 댓글 입력에서, **When** 빈 댓글이나 501자 댓글을 보내면, **Then** 저장되지 않는다.
3. **Given** 비회원이, **When** 댓글을 쓰거나 좋아요를 누르려 하면, **Then** 할 수 없다.
4. **Given** 을의 댓글에, **When** 갑이 답글(대댓글)을 달면, **Then** 답글은 그 댓글 아래 한 단계 들여 보이고, 앞에 "@을의닉네임"이 붙으며, 을에게 "내 댓글에 대댓글" 알림이 간다.
5. **Given** 대댓글이 있을 때, **When** 그 대댓글에 다시 한 단계 더 들어가는 답글을 달려고 하면, **Then** 더 깊은 단계는 만들어지지 않는다(대댓글은 1단계까지).
6. **Given** 갑이 쓴 댓글이 있을 때, **When** 갑이 수정하면, **Then** 내용이 바뀌고 "수정됨"이 표시된다. **When** 다른 회원이 수정·삭제를 요청하면, **Then** 거부된다.
7. **Given** 답글이 달린 댓글을, **When** 작성자가 삭제하면, **Then** 그 자리에 "삭제된 댓글입니다"가 보이고 답글은 그대로 남는다. **Given** 답글이 없는 댓글이면, **Then** 댓글이 목록에서 사라진다.
8. **Given** 회원이 글에 좋아요를 누르지 않았을 때, **When** 좋아요를 누르면, **Then** 좋아요 수가 1 늘고 글 작성자에게 "내 글 좋아요" 알림이 간다. **When** 다시 누르면, **Then** 좋아요가 취소되어 수가 1 줄어든다.
9. **Given** 같은 회원이, **When** 좋아요 요청을 동시에 여러 번 보내면, **Then** 그 글에 그 회원의 좋아요는 많아야 1개만 남는다.
10. **Given** 글 작성자가 "내 글에 댓글" 알림을 꺼 두었을 때, **When** 댓글이 달리면, **Then** 새 알림이 만들어지지 않는다.
11. **Given** 회원이 갑을 차단했고 같은 블로그의 멤버가 아닐 때, **When** 갑이 댓글을 단 글을 열면, **Then** 갑의 댓글은 숨겨진다. **Given** 둘이 같은 블로그의 멤버이면, **Then** 그 블로그 안에서는 보인다.

### 사용자 스토리 6 - 통합 검색과 최근 검색어 (우선순위: P2)

방문자가 메인에서 블로그와 공개 글을 한 번에 검색하고, 분류바로 검색 대상과 정렬을 고른다. 로그인한 회원은 자기 최근 검색어를 보고 지운다.

**이 우선순위인 이유**: 원하는 글과 블로그를 찾는 주된 경로이고 우선순위 "중"이다(BRD-08). 성능 목표(1~2초)가 걸린다(4.2).

**독립 테스트**: 블로그 이름·소개, 글 제목, 태그, 닉네임에 같은 단어를 넣은 데이터를 만들고, 비공개·일부 공개 블로그와 숨김·삭제 글, 차단한 회원의 글을 섞어 두고 검색 결과를 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 블로그 이름·소개, 글 제목, 태그, 작성자 닉네임에 "여행"이 들어간 데이터가 있을 때, **When** "여행"으로 통합 검색하면, **Then** 블로그와 공개 글이 한 번에 나온다.
2. **Given** 검색 화면에서, **When** 분류바로 "태그"만 고르면, **Then** 태그가 정확히 일치하는 글만 나온다. 닉네임 분류도 정확히 일치하는 작성자의 글만 나온다.
3. **Given** 검색창에, **When** 1글자, 21자, 빈칸, 공백만, 특수문자만 있는 검색어를 넣으면, **Then** 검색이 실행되지 않는다(검색어는 2~20자).
4. **Given** 일치하는 결과가 없을 때, **When** 검색하면, **Then** "검색 결과가 없습니다"가 보인다.
5. **Given** 검색 결과가 있을 때, **When** 정렬을 고르지 않으면, **Then** 관련도순으로 나오고, 분류바에서 최신·인기를 고르면 그 순서로 바뀐다. 인기순은 글은 좋아요 수, 블로그는 멤버 수가 많은 순이고 값이 같으면 최신순이다(D-89).
6. **Given** 검색 결과가 35개일 때, **When** 한 페이지 개수를 10·20·30개 중에서 고르면, **Then** 그 개수씩 번호 페이지로 나뉜다.
7. **Given** 비공개·일부 공개 블로그의 글, 숨김·삭제된 글, 내가 차단한 회원의 글에 검색어가 들어 있을 때, **When** 검색하면, **Then** 그 글들은 결과에 나오지 않는다.
8. **Given** 로그인한 회원이 검색어 11개를 차례로 검색했을 때, **When** 최근 검색어를 열면, **Then** 가장 최근 10개만 본인에게만 보인다. **When** 하나의 x를 누르면, **Then** 그것만 지워지고, **When** 전체 삭제를 누르면, **Then** 모두 지워진다.
9. **Given** 회원 갑의 최근 검색어가 있을 때, **When** 회원 을이 최근 검색어를 열면, **Then** 갑의 검색어는 보이지 않는다.

### 사용자 스토리 7 - 태그 (우선순위: P2)

작성자가 글에 태그를 달고, 방문자는 태그를 눌러 같은 태그의 글을 본다. 입력한 태그는 같은 규칙으로 정리되어 같은 태그가 둘로 나뉘지 않는다.

**이 우선순위인 이유**: 글 분류와 검색 품질에 쓰이고 우선순위 "중"이다(BRD-04, 6.4).

**독립 테스트**: 경계값과 정리 규칙에 맞는 태그·맞지 않는 태그를 넣고, 저장된 태그와 태그 링크 결과를 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 글쓰기 화면에서, **When** 태그로 `#맛집`, ` 서울 `, `Java`를 넣으면, **Then** 각각 `맛집`, `서울`, `java`로 저장된다(앞의 `#`과 앞뒤 공백 제거, 영문 소문자).
2. **Given** 태그로 `제주 여행`을 넣으면, **When** 저장하면, **Then** 가운데 공백이 `_`로 바뀌어 `제주_여행`으로 저장된다.
3. **Given** 한 글에, **When** `java`, `Java`, `#java`를 함께 넣으면, **Then** 태그 `java` 하나로 합쳐진다.
4. **Given** 한 글에, **When** 서로 다른 태그 11개를 넣으면, **Then** "글 하나에 최대 10개" 제한으로 저장되지 않는다.
5. **Given** 태그 입력에서, **When** 정리 후 빈 태그나 21자 태그를 넣으면, **Then** "1~20자" 규칙 위반으로 저장되지 않는다.
6. **Given** 태그 입력에서, **When** `c++`, `a.b`처럼 한글·영문·숫자·`_` 외의 문자가 든 태그를 넣으면, **Then** 저장되지 않는다.
7. **Given** 여러 글에 `java` 태그가 있을 때, **When** 방문자가 한 글의 `java` 태그를 누르면, **Then** `java` 태그가 달린 글 목록이 보이고, 비공개·일부 공개 블로그의 글과 삭제된 글은 빠진다.

### 사용자 스토리 8 - 조회수 (우선순위: P3)

글을 열면 조회수가 오른다. 같은 사람이 같은 날 같은 글을 여러 번 열어도 한 번만 센다.

**이 우선순위인 이유**: 운영 참고용이며 우선순위 "하"다(BRD-11). 인기순 정렬은 조회수가 아니라 좋아요 수로 정한다(D-89).

**독립 테스트**: 한 계정으로 같은 글을 같은 날 여러 번 열고 다음 날 다시 열어, 조회수가 하루 1씩만 오르는지 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 조회수 0인 글을, **When** 회원 갑이 처음 열면, **Then** 조회수가 1이 된다.
2. **Given** 갑이 오늘 이미 그 글을 열었을 때, **When** 같은 날 새로고침을 20번 하면, **Then** 조회수는 그대로 1이다.
3. **Given** 갑이 어제 그 글을 열었을 때, **When** 오늘 다시 열면, **Then** 조회수가 1 늘어난다.
4. **Given** 비회원, 회원, 그 블로그의 블로그장이, **When** 각각 그 글을 처음 열면, **Then** 각각 한 번씩 센다.
5. **Given** 같은 사람이, **When** 쿠키를 지운 뒤 같은 날 다시 열면, **Then** 회원이면 다시 세지 않는다.

### 사용자 스토리 9 - 글 링크 공유와 미리보기 (우선순위: P3)

방문자가 글 링크를 복사해 메신저나 SNS에 붙인다. 붙인 곳에서는 주소, 제목(작성자 닉네임 포함), 이미지 순서의 미리보기가 뜬다.

**이 우선순위인 이유**: 바깥으로 블로그를 알리는 기능이지만 우선순위 "하"다(BRD-07). 1차에는 링크 복사만 한다(6.2).

**독립 테스트**: 이미지가 있는 글과 없는 글의 링크를 복사해, SNS 미리보기 검사 도구에서 제목·요약·이미지가 채워지는지 확인하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 공개 블로그의 글 상세 화면에서, **When** 링크 복사 버튼을 누르면, **Then** 그 글의 주소가 복사된다.
2. **Given** 사진이 있는 글의 주소를, **When** SNS나 메신저에 붙이면, **Then** 미리보기에 그 글의 첫 이미지를 줄인 그림이 들어가고, 주소 → 제목(작성자 닉네임까지) → 이미지 순서로 보인다.
3. **Given** 사진이 없는 글의 주소를, **When** 붙이면, **Then** 미리보기 이미지로 블로그 대표 이미지를 줄여서 넣는다.
4. **Given** 스크립트를 실행하지 않는 미리보기 수집기가, **When** 글 상세 주소를 읽으면, **Then** 화면 스크립트 없이도 제목·요약·이미지 정보가 페이지에 들어 있다.
5. **Given** 비공개 블로그의 글 화면에서, **When** 보면, **Then** 공유 버튼이 보이지 않는다.
6. **Given** 링크가 여러 번 공유되었을 때, **When** 어디서든 확인하면, **Then** 공유 수는 세지도 보여주지도 않는다.

### 사용자 스토리 10 - 메인 공지사항 (우선순위: P3)

메인 관리자가 전체 회원에게 공지를 올리고, 회원은 알림으로 받는다.

**이 우선순위인 이유**: 운영 안내용이고 우선순위 "하"다(BRD-10). 공통 게시판 모듈을 메인에서 그대로 쓴다.

**독립 테스트**: 관리자 계정으로 공지를 올리고, 공지 알림을 켜 둔 회원과 꺼 둔 회원의 알림함을 비교하면 된다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 메인 관리자가, **When** 메인 공지사항에 글을 올리면, **Then** 공지가 메인에 보이고 공지 알림을 켜 둔 회원 전원에게 "공지사항" 알림이 간다.
2. **Given** 회원이 공지사항 알림을 꺼 두었을 때, **When** 공지가 올라오면, **Then** 그 회원에게는 새 알림이 만들어지지 않는다.
3. **Given** 일반 회원이나 블로그장이, **When** 메인 공지사항에 글을 쓰려 하면, **Then** 거부된다.

### 엣지 케이스 (Edge Cases)

- **폐쇄 예정 중 글쓰기·댓글**: 폐쇄 버튼을 눌러 7일 유예 중인 블로그도 평소처럼 글쓰기·댓글·좋아요가 된다(BLG-09, D-67). 폐쇄되면 그 블로그의 글·사진·카테고리는 30일 동안 보이지 않고 30일 뒤 완전 삭제된다(4.5, D-35).
- **작성자가 블로그를 떠나거나 강퇴됨**: 그 사람의 글은 남고 작성자가 "탈퇴한 계정"으로 바뀐다(BLG-07, BLG-11, D-33). 떠난 뒤에는 그 글을 수정할 수 없다(멤버만 글을 쓰고 본인 글만 수정, 2장). 떠난 뒤에는 그 블로그에 남은 자기 글을 수정·삭제할 수 없다(필요하면 블로그장이 지운다). 그 사람의 댓글은 닉네임 그대로 둔다. [D-100 #1]
- **작성자가 회원탈퇴**: 글은 "탈퇴한 회원"으로 표시되어 남는다(USR-05, D-05). 탈퇴한 회원의 닉네임은 검색의 닉네임 일치 대상에서 빠진다(4.5 개인정보 30일 뒤 삭제, 화면에 안 보임). 탈퇴한 회원의 댓글은 내용을 남기고 작성자를 "탈퇴한 회원"으로 표시한다. [D-100 #2]
- **답글 있는 댓글 삭제 후 답글도 삭제**: 부모 댓글은 "삭제된 댓글입니다"로 남는다(6.6). 그 아래 답글이 모두 지워지면 "삭제된 댓글입니다" 자리도 없앤다. [D-100 #3]
- **좋아요·댓글 동시 요청**: 같은 회원이 좋아요를 빠르게 여러 번 눌러도 한 글에 한 회원의 좋아요는 하나뿐이다(6.5). 좋아요 요청에는 트래픽 제한을 건다(6.5).
- **조회수 동시 요청**: 같은 사람이 같은 글을 같은 순간 두 탭에서 열어도 그날 한 번만 센다(6.7, D-77).
- **날짜 경계**: 23:59와 다음 날 00:01에 같은 글을 열면 두 번 센다(하루 단위, 6.7).
- **글 삭제와 이미지**: 삭제한 글의 사진도 30일 동안 보이지 않고 30일 뒤 완전 삭제된다(4.5). 실수나 잘못된 삭제는 30일 안에 관리자가 복구할 수 있다(4.5).
- **글을 쓰다가 올린 사진만 남는 경우**: 어느 글에도 쓰이지 않는 사진(올리고 글을 저장하지 않았거나 본문에서 지운 사진)은 올린 지 하루가 지나면 04:00 처리에서 지움 표시를 하고, 파일은 30일 뒤 지운다. [D-100 #4]
- **본문 길이와 이미지**: 본문 5,000자는 보이는 글자가 아니라 저장하는 마크다운 원문으로 세며 공백과 마크다운 기호를 모두 포함한다. 글자 수는 화면이 아니라 서버에서 검사한다(6.6, D-92).
- **차단과 같은 블로그**: 차단한 회원의 글·댓글은 피드·검색·댓글에서 숨기지만, 같은 블로그의 멤버끼리는 그 블로그 안의 글이 보인다(SOC-05, D-36).
- **비공개 전환과 구독자**: 블로그가 비공개로 바뀌면 멤버가 아닌 구독자에게는 그 블로그의 글이 피드·검색·글 상세에서 보이지 않고, 구독과 알림은 유지된다(BLG-01, D-37). 다시 공개로 바뀌면 이어서 보인다.
- **일부 공개 블로그의 글**: 목록·검색·피드에는 나오지 않고 공유 링크로 들어온 사람만 본다(BLG-01, D-49, D-50). 공유 버튼은 글 주소에 블로그 공유 링크 값을 붙여 복사하고, 글 주소만 알아서는 볼 수 없다. [D-100 #5]
- **일부 공개 글의 미리보기**: 공유 링크 값이 맞는 주소일 때만 미리보기 수집기에게 제목·요약·이미지를 보여주고, 값이 없거나 틀리면 사이트 기본 미리보기만 보여준다. [D-100 #6]
- **정지된 회원**: 정지 기간 동안 그 블로그에는 들어갈 수 없으므로 그 블로그에 글·댓글을 쓸 수 없다(BLG-13). 다른 블로그는 그대로 쓴다.
- **응답이 느릴 때**: 메인·목록·검색 결과가 5초를 넘기면 계속 기다리게 두지 않고 중단한 뒤 다시 시도하라고 안내한다(4.2, D-48).
- **글쓰기 중 로그인 만료**: 글쓰기 화면에서 입력이 있으면 로그인을 연장하고, 만료 5분 전에 "로그인을 연장할까요?" 창을 띄운다(SEC-04, D-62). 만료되어도 브라우저 자동 저장 내용은 남는다(6.6).
- **가입 여부·개인정보 노출 방지**: 글·댓글·검색·피드 응답에는 작성자의 닉네임과 프로필 사진만 담고, 이메일·이름·전화번호는 담지 않는다(4.4, D-22). 검색의 닉네임 일치 결과로 이메일 가입 여부를 알 수 없다.
- **이미지 파일 이름**: 원래 파일 이름에 경로 문자나 스크립트가 들어 있어도 서버 저장 이름은 무작위 고유 이름이고, 원래 이름은 기록으로만 남는다(6.3).

## 요구사항 (Requirements) *(필수)*

### 기능 요구사항 (Functional Requirements)

#### 공통 모듈

- **FR-001**: 시스템은 게시판(글·목록·카테고리·태그·이미지·댓글·좋아요·공유·조회수)을 하나의 공통 기능으로 두어 메인 공지사항과 모든 개별 블로그가 같은 규칙으로 쓰게 해야 한다. 통합 검색, 메인 피드, 공지사항은 메인에만 둔다. [3.4, 5장]

#### 글 쓰기·조회·수정·삭제

- **FR-002**: 시스템은 블로그 멤버(블로그장·부블로그장 포함)가 블로그에 제목과 본문으로 글을 쓰게 하고, 비회원, 그 블로그의 멤버가 아닌 회원, 메인 관리자 계정은 쓰지 못하게 해야 한다. 메인 관리자 계정(role = ADMIN)의 글쓰기는 메인 공지(BRD-10, FR-065)만 허용한다. [BRD-01, 2장 기능별 권한, 2장 회원 표, SEC-09, D-90]
- **FR-003**: 시스템은 글 제목을 1~30자, 본문을 최대 5,000자로 제한해야 한다. 본문 글자 수는 공백·마크다운 기호를 포함한 마크다운 원문으로 세고, 서버에서 검사해야 한다. [6.6, D-92]
- **FR-004**: 시스템은 본문을 마크다운으로 입력·저장하고, 입력·미리보기·툴바·이미지 올리기가 있는 마크다운 에디터를 제공해야 한다. [6.6 에디터, BRD-01, D-74]
- **FR-005**: 시스템은 글을 보여줄 때 서버에서 마크다운을 HTML로 바꾼 뒤 허용하지 않은 태그·속성(스크립트, 이벤트 속성 등)을 제거하고, 걸러진 본문만 HTML로 표시해야 한다. 화면이 아닌 경로(직접 요청)로 받은 본문도 같은 방식으로 걸러야 한다. [SEC-06, 6.6, D-64, 7장 XSS 걸러내는 위치]
- **FR-006**: 시스템은 본문을 제외한 사용자 입력(제목, 닉네임, 댓글, 태그, 검색어 등)을 화면에 HTML로 해석하지 않고 글자 그대로 표시해야 한다. [SEC-06, 7장 화면 방식, D-64, D-66]
- **FR-007**: 시스템은 모든 입력값을 서버에서 검증하고, 입력값이 데이터 조회 명령으로 해석되지 않게(SQL Injection 방지) 처리해야 한다. [SEC-06]
- **FR-008**: 시스템은 글 수정을 작성자 본인만 할 수 있게 하고, 블로그장·부블로그장·메인 관리자를 포함한 다른 누구도 남의 글을 수정하지 못하게 해야 한다. [BRD-01, 2장 기능별 권한, D-07, D-58]
- **FR-009**: 시스템은 글 삭제를 작성자 본인, 그 블로그의 블로그장(자기 블로그 글만, 글 관리 권한을 받은 부블로그장 포함), 메인 관리자만 할 수 있게 해야 한다. 다른 블로그의 블로그장은 삭제할 수 없어야 한다. [BRD-01, 2장 기능별 권한, 2장 블로그장 표, SEC-07, D-07, D-58]
- **FR-010**: 시스템은 글 수정·삭제 권한을 요청마다 서버에서 그 블로그에서의 현재 역할로 확인해야 한다. [SEC-07, BRD-01]
- **FR-011**: 시스템은 메인 관리자나 블로그장(부블로그장 포함)이 남의 글을 삭제하면 작성자에게 "내 글 삭제됨" 알림을 보내야 하며, 이 알림은 끌 수 없어야 한다. [BRD-01, 3.6, 2장 회원 표]
- **FR-012**: 시스템은 글 삭제 전에 "글을 정말 삭제하시겠습니까" 확인을 받아야 한다. [6.3 글 삭제 시]
- **FR-013**: 시스템은 삭제한 글·댓글·사진을 삭제한 날부터 30일 동안 화면(상세·목록·검색·피드)에 보이지 않게 보관하고, 그 동안 관리자가 복구할 수 있게 하며, 30일 뒤 완전 삭제해야 한다. [4.5, D-40]
- **FR-014**: 시스템은 글쓰기 중인 내용을 1차에는 사용자의 브라우저에만 자동 저장하고, 같은 브라우저에서 다시 열면 이어 쓰게 해야 한다. [6.6 임시저장]
- **FR-015**: 시스템은 폐쇄 예정(7일 유예) 중인 블로그에서도 글쓰기·수정·삭제·댓글을 평소처럼 허용해야 한다. [BLG-09, D-67]
- **FR-016**: 시스템은 블로그를 떠나거나 강퇴된 멤버의 글 작성자를 "탈퇴한 계정"으로, 회원탈퇴한 회원의 글 작성자를 "탈퇴한 회원"으로 표시하고 글은 남겨야 한다. [BLG-07, BLG-11, USR-05, D-05, D-33]

#### 목록·페이징

- **FR-017**: 시스템은 글 목록을 최신순으로 보여주고, 한 페이지 개수를 사용자가 10·20·30개 중에서 고르게 하며, 처음 기본값은 10개로 해야 한다. 다른 개수는 받지 않아야 한다. [BRD-02, 6.6 페이징 기본값, D-06]
- **FR-018**: 시스템은 목록을 번호 페이지로 나눠, 원하는 페이지로 바로 이동하게 해야 한다. [BRD-02, D-76, 7장 목록 넘기기]
- **FR-019**: 시스템은 목록용 썸네일을 따로 만들지 않고 원본 이미지를 줄여 표시하며, 목록에서 글 제목에 마우스 포인터를 올리면 그 글의 사진을 보여줘야 한다. [6.3 썸네일] 보여 줄 사진은 본문의 첫 사진이고, 마우스 포인터가 없는 휴대폰에서는 목록 줄 오른쪽에 첫 사진을 작게 늘 보여준다. [D-100 #7]
- **FR-020**: 시스템은 목록·상세·검색·피드에서 보는 사람이 볼 수 없는 글(비공개 블로그의 글은 멤버가 아닌 사람에게, 일부 공개 블로그의 글은 공유 링크로 들어오지 않은 사람에게, 숨김·삭제된 글은 모두에게)을 서버 응답에서 빼야 한다. [BLG-01, D-37, D-49, 6.1, 4.5]

#### 카테고리

- **FR-021**: 시스템은 글을 카테고리로 분류하게 하고, 카테고리를 누르면 그 카테고리의 글만 보여줘야 한다. [BRD-03]
- **FR-022**: 시스템은 카테고리 관리(추가·수정·삭제)를 블로그장과 글 관리 권한을 받은 부블로그장만 하게 해야 한다. [BRD-03, 2장 블로그장 표] 카테고리 없이 글을 쓸 수 있고("미분류"), 카테고리를 지우면 그 글은 미분류로 옮긴다. 카테고리는 블로그당 최대 30개, 이름은 1~30자이고 숫자는 설정값으로 둔다. [D-100 #8, D-68]

#### 태그

- **FR-023**: 시스템은 글에 태그를 달게 하고, 태그를 누르면 같은 태그가 달린 글 목록을 보여줘야 한다. 이 목록에도 FR-020의 보이지 않는 글 규칙을 적용해야 한다. [BRD-04]
- **FR-024**: 시스템은 글 하나에 태그를 최대 10개까지만 받아야 한다. [6.4 개수]
- **FR-025**: 시스템은 입력된 태그에서 앞의 `#`과 앞뒤 공백을 지우고, 가운데 공백은 `_`로 바꾸고, 영문은 소문자로 바꿔 저장해야 한다. [6.4 입력 정리, 6.4 중복(대소문자)]
- **FR-026**: 시스템은 정리한 뒤의 태그가 1~20자이고 한글·영문·숫자·`_`로만 되어 있을 때만 받아야 한다. [6.4 길이, 6.4 허용 문자]
- **FR-027**: 시스템은 한 글 안에서 정리 후 같은 태그가 여러 번 들어오면 하나로 합쳐야 한다. [6.4 중복(한 글 안)]
- **FR-028**: 시스템은 태그 금칙어(욕설 목록) 검사를 두지 않아야 한다. 태그는 FR-024~FR-027의 개수·길이·허용 문자·정리 규칙만 적용한다. [6.4 금칙어, D-96]

#### 이미지 첨부

- **FR-029**: 시스템은 글 이미지로 jpg, jpeg, png, gif, webp 형식만 받고, svg·동영상·문서(pdf, hwp 등)·압축 파일과 실행 파일은 받지 않아야 한다. [BRD-05, SEC-08, 6.3 허용 형식, 6.3 제외 형식]
- **FR-030**: 시스템은 올린 파일의 확장자, 파일 형식 정보(MIME: jpg, jpeg, png, gif, webp), 파일 앞부분 바이트(파일 시그니처)를 모두 확인하고, 하나라도 맞지 않으면 받지 않아야 한다. [SEC-08, 6.3 검증 방법]
- **FR-031**: 시스템은 글 이미지를 장당 3MB, 글 하나에 최대 10장, 한 번에 보내는 용량 최대 10MB로 제한해야 한다. [BRD-05, SEC-08, 6.3 글 이미지 크기·개수]
- **FR-032**: 시스템은 프로필 사진과 블로그 대표 이미지를 1장, 3MB 이하로 제한하고 글 이미지와 같은 형식·검증 규칙을 적용해야 한다. [6.3 프로필·블로그 대표 이미지, SEC-08]
- **FR-033**: 시스템은 올린 파일을 서버에서 무작위 고유 이름(UUID)으로 저장하고, 원래 파일 이름은 기록으로만 보관해야 한다. [6.3 저장 방식]
- **FR-034**: 시스템은 올린 사진에서 위치 정보(GPS 등 EXIF)를 지운 뒤 저장해야 한다. [6.3 위치 정보]
- **FR-035**: 시스템은 이미지 저장 위치를 바꿔도(1차 서버 디스크, 이중화 때 외부 저장소) 업로드·표시 기능이 그대로 동작하도록 저장 방식을 다른 기능과 분리해야 한다. [7장 이미지 저장, D-75, SCL-02]

#### 댓글·대댓글·좋아요

- **FR-036**: 시스템은 로그인한 회원이 볼 수 있는 글에 댓글을 달게 하고, 비회원과 메인 관리자 계정은 댓글을 쓰지 못하게 해야 한다. [BRD-06, 2장 기능별 권한, 2장 회원 표, D-90] 공유 링크로 들어와 글을 볼 수 있는 회원은 일부 공개 블로그의 글에도 댓글·좋아요를 할 수 있다. [D-100 #9]
- **FR-037**: 시스템은 댓글을 1~500자로 제한해야 한다. [6.6 댓글 길이]
- **FR-038**: 시스템은 댓글에 답글(대댓글)을 1단계까지만 달게 하고, 답글 앞에 답한 대상의 "@닉네임"을 표시해야 한다. 대댓글 아래에 더 깊은 단계는 만들지 않아야 한다. 답한 대상은 닉네임 글자가 아니라 대상 회원으로 저장해, 대상이 닉네임을 바꾸면 바뀐 닉네임이 보이게 해야 한다. [BRD-06, 6.6 대댓글 깊이, D-78, D-87, 7장 대댓글] 대댓글에 "답글"을 누르면 같은 1단계에 그 대댓글 작성자의 "@닉네임"을 붙여 단다(태그식). [D-87, D-100 #10]
- **FR-039**: 시스템은 댓글 수정·삭제를 작성자 본인만 하게 해야 한다(메인 관리자의 댓글 숨김·삭제는 ADM-03). [2장 회원 표, ADM-03] 블로그장과 글 관리 권한을 받은 부블로그장은 자기 블로그의 남의 댓글을 삭제할 수 있고, 답글이 있으면 "삭제된 댓글입니다"로 남는다. [D-100 #11]
- **FR-040**: 시스템은 수정한 댓글에 "수정됨"을 표시해야 한다. 글에는 수정 표시를 하지 않는다. [6.6 수정 표시]
- **FR-041**: 시스템은 답글이 있는 댓글을 삭제하면 그 자리를 "삭제된 댓글입니다"로 표시하고 답글은 남겨야 한다. [6.6 댓글 삭제]
- **FR-042**: 시스템은 로그인한 회원이 글에 좋아요를 한 번만 누르게 하고, 다시 누르면 취소되게 하며, 동시에 여러 번 요청해도 한 회원의 좋아요가 하나를 넘지 않게 해야 한다. 메인 관리자 계정은 좋아요를 누를 수 없어야 한다. [BRD-06, 6.5 좋아요, D-90]
- **FR-043**: 시스템은 좋아요 요청에 트래픽 제한을 걸어야 한다. [6.5 좋아요] 좋아요 요청은 회원 한 명당 1분에 30번까지로 하고 숫자는 설정값으로 둔다. [D-100 #12, D-68]
- **FR-044**: 시스템은 내 글에 댓글이 달리면 글 작성자에게, 내 댓글에 대댓글이 달리면 댓글 작성자에게, 내 글에 좋아요가 눌리면 글 작성자에게 알림을 보내고, 받는 사람이 그 알림을 꺼 두었으면 새 알림을 만들지 않아야 한다. [BRD-06, SOC-04, 3.6] 자기 글에 자기가 한 댓글·좋아요는 알리지 않고, 같은 사람이 같은 글에 취소 후 다시 누른 좋아요는 다시 알리지 않는다. [D-100 #13]
- **FR-045**: 시스템은 내가 차단한 회원의 글과 댓글을 피드·검색·댓글 목록에서 숨기되, 같은 블로그의 멤버끼리는 그 블로그 안의 글이 보이게 해야 한다. [SOC-05, D-36, 6.1]

#### 공유

- **FR-046**: 시스템은 글 상세 화면에서 글 링크를 복사하는 공유 기능을 1차에 제공해야 한다. [BRD-07, 6.2 공유 수단]
- **FR-047**: 시스템은 비공개 블로그의 글에는 공유 버튼을 보여주지 않아야 한다. [BLG-01, D-49]
- **FR-048**: 시스템은 글 상세 주소에 한해 서버가 페이지에 제목·요약·대표 이미지 미리보기 정보(Open Graph)를 채워서 내려줘, 스크립트를 실행하지 않는 SNS 미리보기 수집기도 읽을 수 있게 해야 한다. [BRD-07, 6.2 미리보기, D-66, 7장 화면 방식] 미리보기 요약은 마크다운 기호를 뺀 본문 앞 100자로 만든다(설정값). [D-100 #14]
- **FR-049**: 시스템은 미리보기 이미지로 글의 첫 이미지를 줄여서 넣고, 글에 이미지가 없으면 블로그 대표 이미지를 줄여서 넣어야 한다. [BRD-07, D-59] 블로그 대표 이미지도 없으면 사이트 기본 이미지 1장을 넣는다. [D-100 #15]
- **FR-050**: 시스템은 미리보기를 주소 → 제목(작성자 닉네임까지) → 이미지 순서로 구성해야 한다. [BRD-07, 6.2 미리보기, D-59]
- **FR-051**: 시스템은 공유 수를 세거나 표시하지 않아야 한다. [6.2 공유 수 집계]

#### 통합 검색 (메인 전용)

- **FR-052**: 시스템은 메인에서 블로그(이름·소개), 글 제목, 태그, 작성자 닉네임을 한 번에 검색하고, 분류바로 검색 대상을 골라 검색하게 해야 한다. 비회원도 검색할 수 있어야 한다. [BRD-08, 2장 기능별 권한, 2장 회원 표]
- **FR-053**: 시스템은 블로그와 글 제목은 2글자 단위 부분 일치(ngram 전문 검색)로, 태그와 닉네임은 정확히 일치하는 것만 찾아야 한다. [BRD-08]
- **FR-054**: 시스템은 검색어를 2~20자로 제한하고, 빈칸·공백·특수문자만 있는 검색어는 검색하지 않아야 한다. [BRD-08, 6.1 검색어 길이]
- **FR-055**: 시스템은 검색 결과가 없으면 "검색 결과가 없습니다"를 보여줘야 한다. [BRD-08]
- **FR-056**: 시스템은 검색 결과를 관련도순(기본), 최신순, 인기순으로 분류바에서 골라 정렬하게 해야 한다. 인기순은 글은 좋아요 수, 블로그는 멤버 수가 많은 순으로 하고, 값이 같으면 최신순으로 정렬해야 한다(메인 피드 FR-061, 블로그 목록 BLG-02와 같은 기준). [6.1 정렬, D-89]
- **FR-057**: 시스템은 검색 결과를 한 페이지 10·20·30개 중에서 고르게 하고(기본 10개) 번호 페이지로 나눠야 한다. [BRD-08, 6.6 페이징 기본값, D-76]
- **FR-058**: 시스템은 비공개 블로그, 일부 공개 블로그와 그 글, 숨김·삭제된 글, 내가 차단한 회원의 글을 검색 결과에서 빼야 한다. [6.1 결과에서 제외, BLG-01, D-49] 비공개 블로그는 결과에서 아예 빼고 결과 개수에도 넣지 않는다. [D-100 #16]
- **FR-059**: 시스템은 로그인한 회원의 최근 검색어를 본인에게만 최대 10개(최근 것부터) 보여주고, 하나씩(x) 지우기와 전체 삭제를 제공해야 한다. [6.1 부가 기능, 2장 회원 표] 같은 검색어를 다시 검색하면 맨 앞으로 옮기고(중복 없음), 비회원에게는 최근 검색어를 제공하지 않는다. [D-100 #17]
- **FR-060**: 시스템은 1차에 검색어 자동완성을 제공하지 않아야 한다. [6.1 부가 기능]

#### 메인 피드 (메인 전용)

- **FR-061**: 시스템은 메인 피드에 전체 공개 블로그의 최신 공개 글과 인기 공개 글을 보여줘야 한다. 인기 글은 좋아요 수가 많은 순으로, 좋아요 수가 같으면 최신순으로 정렬해야 한다. 일부 공개·비공개 블로그의 글은 넣지 않아야 한다. [BRD-09, BLG-01, D-49, D-89]
- **FR-062**: 시스템은 로그인한 회원에게 팔로우한 회원의 새 글과 구독한 블로그의 새 글을 탭을 나눠 보여주고, 두 목록을 섞지 않아야 한다. [BRD-09, SOC-01, D-65, D-02]
- **FR-063**: 시스템은 피드를 볼 때마다 그 시점의 글을 모아 보여줘, 글 삭제·차단·비공개 전환이 다음 조회에 바로 반영되게 해야 한다. [BRD-09, D-73, 7장 메인 피드]
- **FR-064**: 시스템은 팔로우·구독 탭에도 FR-020의 보이지 않는 글 규칙과 FR-045의 차단 규칙을 적용해, 비공개로 바뀐 블로그의 글은 멤버가 아닌 구독자에게 보이지 않게 해야 한다. [BRD-09, D-37, SOC-05] "새 글"은 최근 30일 글이고, 한 번에 20개씩 아래 "더 보기" 버튼으로 이어서 보여준다(설정값). [D-100 #18]

#### 공지사항 (메인 전용)

- **FR-065**: 시스템은 메인 관리자만 메인 공지사항을 쓰게 하고(메인 관리자의 글쓰기는 메인 공지만 허용, D-90), 공지를 올리면 공지사항 알림을 켜 둔 전체 회원에게 알림을 보내야 한다. 회원은 이 알림을 끌 수 있어야 한다. [BRD-10, 3.6, D-90] 공지사항은 메인 관리자면 누구나 수정·삭제할 수 있고, 공지에는 댓글·좋아요를 달지 않는다. [D-100 #19]

#### 조회수

- **FR-066**: 시스템은 비회원·회원·블로그장 구분 없이 글을 열면 조회수를 세되, 같은 사람이 같은 날 같은 글을 여러 번 보면 1번만 세야 한다. [BRD-11, 6.7 조회수] 비회원은 브라우저에 두는 무작위 값 쿠키(1년)로 구분하고, 작성자 본인의 조회는 세지 않는다. [D-100 #20]
- **FR-067**: 시스템은 조회 기록을 서버의 저장소에 남겨 "같은 사람 하루 1번" 규칙을 지키게 하고, 사용자가 쿠키를 지워도 회원은 다시 세지 않아야 한다. 서버를 여러 대로 늘려도 같은 결과가 나와야 한다. [BRD-11, D-77, 7장 조회수, SCL-01, 4.3 이중화할 때 바뀌는 점]
- **FR-068**: 시스템은 봇(뷰봇)이 조회수를 부풀리지 못하게 해야 한다. [BRD-11, 6.7 조회수] 같은 접속 주소(IP)에서 1분에 글 60개를 넘게 열거나 브라우저 정보(User-Agent)에 bot·crawler·spider 같은 말이 있으면 조회수에 넣지 않는다(글은 정상으로 보인다, 설정값). [D-100 #21]

#### 성능·사용성

- **FR-069**: 시스템은 메인 화면(피드), 글 목록, 검색 결과를 목표 1초, 늦어도 2초 안에 응답해야 한다. [4.2 성능, D-48]
- **FR-070**: 시스템은 메인·목록·검색 응답이 5초를 넘기면 기다리게 두지 않고 중단한 뒤 다시 시도하라고 안내해야 한다. [4.2 성능, D-48]
- **FR-071**: 시스템은 글쓰기·글 상세·목록·검색·피드 화면을 PC와 모바일에서 모두 쓸 수 있게(반응형) 해야 한다. [4.2 사용성]
- **FR-072**: 시스템은 개별 블로그의 글 화면에서도 메인으로 돌아가는 상단 메뉴와 로그인 상태를 메인과 같게 보여줘야 한다. [4.2 일관성]
- **FR-073**: 시스템은 글·댓글·검색·피드 응답에 작성자의 닉네임·프로필 사진만 담고, 이메일·이름·전화번호는 담지 않아야 한다. [4.4, D-22]

### 핵심 엔터티 (Key Entities) *(데이터를 다루는 경우 포함)*

- **게시판**: 글이 속하는 곳. 메인 공지사항 또는 개별 블로그 하나. 블로그의 공개 범위·상태(운영 중·폐쇄 예정·폐쇄됨)에 따라 글이 보이는지가 정해진다.
- **글**: 게시판, 작성자(회원), 카테고리(선택), 제목(1~30자), 본문(마크다운 원문, 공백·마크다운 기호 포함 최대 5,000자, D-92), 작성 시각, 수정 시각, 상태(보임·숨김·삭제), 삭제 시각(30일 보관 기준), 삭제한 사람, 조회수, 좋아요 수. 작성자가 블로그를 떠나면 "탈퇴한 계정", 회원탈퇴하면 "탈퇴한 회원"으로 표시된다.
- **카테고리**: 블로그 하나에 속하는 분류. 이름. 블로그장(또는 글 관리 권한을 받은 부블로그장)이 관리한다.
- **태그**: 정리된 태그 이름(1~20자, 한글·영문 소문자·숫자·`_`). 같은 이름은 하나다.
- **글-태그 연결**: 글과 태그의 관계. 한 글에 최대 10개, 한 글 안에서 같은 태그는 하나.
- **첨부 이미지**: 글(또는 프로필·블로그 대표 이미지), 저장 이름(무작위 고유값), 원래 파일 이름, 형식, 크기(3MB 이하), 올린 시각, 삭제 시각. 위치 정보는 지운 상태로 저장된다. 글 하나에 최대 10장.
- **댓글**: 글, 작성자, 부모 댓글(대댓글이면 1단계 위 댓글, 없으면 최상위), 답할 대상 회원(@닉네임 표시용, 닉네임 글자가 아니라 회원을 저장, D-87), 내용(1~500자), 작성 시각, 수정 여부("수정됨" 표시), 상태(보임·삭제), 삭제 시각.
- **좋아요**: 회원과 글의 관계. 한 회원이 한 글에 하나만 가진다. 누른 시각.
- **조회 기록**: 글, 본 사람(회원 또는 비회원을 구분하는 값), 본 날짜. 같은 글·같은 사람·같은 날은 하나만 있다.
- **최근 검색어**: 회원, 검색어(2~20자), 검색한 시각. 회원당 최근 10개만 보인다.
- **공유 미리보기 정보**: 글 상세 주소, 제목, 작성자 닉네임, 요약, 대표 이미지(글의 첫 이미지 또는 블로그 대표 이미지). 글에서 만들어지며 따로 저장하지 않아도 된다.
- **공지사항**: 메인 게시판의 글. 메인 관리자가 쓴다. 공지사항 알림의 근거가 된다.

## 성공 기준 (Success Criteria) *(필수)*

### 측정 가능한 결과 (Measurable Outcomes)

- **SC-001**: 메인 피드, 글 목록, 검색 결과는 목표 1초, 늦어도 2초 안에 응답하고, 5초를 넘기면 중단 후 다시 시도 안내가 보이며 무한히 기다리는 화면은 0건이다. [4.2, D-48]
- **SC-002**: 스크립트·이벤트 속성·위험한 링크가 든 본문·제목·닉네임·댓글·태그 공격 사례 모음을 넣었을 때, 어느 화면에서도 스크립트가 실행되는 경우가 0건이다(화면을 거치지 않고 직접 보낸 요청 포함). [SEC-06, D-64]
- **SC-003**: 허용하지 않은 형식, 확장자만 바꾼 실행 파일, 3MB 초과, 11장째, 한 번에 10MB 초과 업로드 시도가 100% 막히고, 저장된 사진에서 위치 정보가 발견되는 경우가 0건이다. [SEC-08, 6.3]
- **SC-004**: 작성자가 아닌 사람(블로그장·메인 관리자 포함)의 글 수정 요청과, 권한 없는 사람(다른 블로그의 블로그장 포함)의 글 삭제 요청이 100% 거부된다. [BRD-01, SEC-07, D-07, D-58]
- **SC-005**: 같은 사람이 같은 날 같은 글을 100번 열어도 조회수는 1만 오르고, 회원이 쿠키를 지운 뒤 다시 열어도 늘지 않는다. [BRD-11, 6.7, D-77]
- **SC-006**: 같은 회원이 한 글에 좋아요 요청을 동시에 10번 보내는 테스트를 반복해도 그 회원의 좋아요가 2개 이상 남는 경우가 0건이다. [6.5]
- **SC-007**: 비공개·일부 공개 블로그의 글, 숨김·삭제된 글, 차단한 회원의 글(같은 블로그 멤버 예외 제외)이 검색 결과·메인 피드·태그 목록에 나오는 경우가 0건이다. [6.1, BLG-01, SOC-05]
- **SC-008**: 글 삭제·작성자 차단·비공개 전환 직후 다음 피드 조회에서 해당 글이 보이는 경우가 0건이다. [D-73]
- **SC-009**: 6.4 정리 규칙의 예시(`#맛집`, ` 서울 `, `Java`, `제주 여행`, `java`/`Java` 중복)가 모두 규칙대로 저장되고, 11개째 태그·21자 태그·허용하지 않은 문자가 든 태그는 100% 거부된다. [6.4]
- **SC-010**: 이미지가 있는 글과 없는 글의 주소를 SNS 미리보기 검사 도구에 넣으면 100% 제목·요약·이미지가 채워지고, 이미지가 없는 글은 블로그 대표 이미지가 들어간다. [BRD-07, D-59, D-66]
- **SC-011**: 글·댓글·검색·피드 응답 어디에도 다른 회원의 이메일·이름·전화번호가 들어간 경우가 0건이다. [4.4, D-22]
- **SC-012**: 삭제한 글·댓글·사진은 삭제 후 30일 동안 화면에 0건 노출되고, 30일 뒤 처리에서 모두 완전 삭제된다. [4.5, D-40]
- **SC-013**: 글쓰기, 글 상세, 목록, 검색, 피드 화면을 PC와 모바일 화면에서 모두 쓸 수 있고, 개별 블로그 화면에서도 메인과 같은 상단 메뉴·로그인 상태가 보인다. [4.2]

## 가정 (Assumptions)

- **1차 공유 수단**: 1차에는 링크 복사만 제공한다. 카카오톡(공식 공유 기능 이용), X, 페이스북, 인스타, 텔레그램 공유는 2차다(6.2).
- **1차 검색 부가 기능**: 1차에는 최근 검색어만 제공하고, 자동완성은 검색 기록 저장·집계가 따로 필요하므로 넣지 않는다(6.1).
- **1차 임시저장**: 글쓰기 자동 저장은 1차에 브라우저에만 하고, 서버 저장은 하지 않는다(6.6).
- **1차 썸네일**: 목록용 썸네일을 따로 만들지 않고 원본을 줄여 표시한다. 느리면 2차에 추가한다(6.3).
- **1차 이미지 저장**: 이미지는 1차에 서버 디스크에 저장하고, 서버를 늘릴 때 외부 저장소로 옮긴다(D-75, SCL-02).
- **1차 피드 방식**: 메인 피드는 볼 때마다 모아오며, 성능 목표(4.2)를 넘기면 다시 검토한다(D-73).
- **1차 서버 1대**: 서버 1대로 운영하되 조회 기록 등 상태는 서버 메모리에 두지 않는다(4.3, SCL-01).
- **날짜 기준**: 조회수의 "같은 날", 30일 보관 계산은 한국 시간 기준으로 본다(7장 폐쇄 처리의 시간대 기준과 같게). 완전 삭제는 매일 새벽 4시 처리에서 함께 한다(4.5).
- **범위 밖**: 개별 블로그 내부 기능(블로그 꾸미기, 블로그별 카테고리 운영 세부, 블로그 공지)은 별도 문서에서 다룬다(1장, 5장). 메인 관리자의 글·댓글 숨김·삭제 화면(ADM-03), 신고(SOC-06), 알림 전달·설정 화면(SOC-04, 3.6, D-72), 팔로우·구독(SOC-01), 차단(SOC-05)은 각 기능 명세에서 다루고, 이 명세는 게시판에 주는 결과만 정한다.
- **DB 설계**: 엔터티의 물리 설계(ERD)는 요구사항 정리 뒤에 한다(D-47). 글 본문의 DB 타입은 TEXT로 둔다(5,000자 제한을 바꿔도 DB를 고치지 않기 위해, D-92).
- **의존 기능**: 회원 계정과 로그인(USR-01~05, SEC-04, D-53, D-62), 블로그별 역할과 공개 범위(BLG-01, SEC-07, 002-blog-management), 블로그 정지(BLG-13), 알림(SOC-04, 3.6).
- **기술 선택(plan.md에서 다룸)**: 에디터는 Toast UI Editor(D-74), 본문 걸러내기는 서버에서 jsoup(D-64), 화면은 정적 HTML + JS이며 글 상세의 og 태그만 서버가 채움(D-66), 상태를 바꾸는 요청은 CSRF 토큰 확인(SEC-10), 보안 헤더·CSP(SEC-12), 블로그·글 제목 검색은 MySQL FULLTEXT + ngram(BRD-08), 이미지 저장은 `FileStorage` 인터페이스(SCL-02, D-75), 조회수는 DB 조회 기록 테이블(D-77), 태그 중복은 DB의 `uk_post_tags`로 막음(6.4), 카카오톡 공유는 2차에 Kakao JavaScript SDK(6.2), 블로그별 역할 확인은 Spring Security `@PreAuthorize`(SEC-11, D-09).
