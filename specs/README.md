# specs

## 확인 필요 항목

문서에 없거나 문서끼리 맞지 않는 부분은 지어내지 않고 `[NEEDS CLARIFICATION: …]`으로 남겼습니다. 규칙을 정하면 `/speckit-clarify`로 명세에 반영하고, 결정이면 `docs/03-decisions/`에 D-번호를 추가합니다.

정한 것 (2026-10-07) — 여러 명세에 걸치거나 문서끼리 충돌하던 7개 항목:
1. 2장 권한 표의 메인 관리자 "참여 승인·멤버 강퇴" → 2장 표를 X로 고쳐 ADM-01·D-44에 맞춤 (D-90, 002·005)
2. SEC-09 관리자 계정 분리 → 관리자 계정은 일반 회원과 분리하고 블로그 활동(생성·참여 신청·글쓰기·댓글·좋아요·팔로우)을 하지 않음 (D-90, 002·003·004·005)
3. 블로그장이 쓴 글·댓글, 메인 프로필 회원 신고의 접수처 → 메인 관리자 (D-93, 002·003·005)
4. 관리자 강제 폐쇄 → 누른 날짜 + 7일 04:00, 블로그장 폐쇄와 같은 알림, 철회는 메인 관리자만 (D-94, D-104, 002·003·005)
5. 경고·정지 횟수 → 블로그별로 세고 3회 기준, 1년 지난 것은 뺌 (D-95, 002·005)
6. 인기순 기준 → 블로그는 멤버 수, 글은 좋아요 수, 같으면 최신순 (D-89, 002·004)
7. 6.4 태그 금칙어 → 만들지 않음 (D-96, 004)

요구사항분석서 2026-10-07판으로 정해진 것 (D-83~D-92):
- 만 14세 확인 체크 → 두지 않음 (D-91, 001)
- 블로그 태그를 누가 다는지 → 블로그를 만들 때 최대 10개, 6.4 규칙 (D-88, 002)
- 블랙리스트 보관 끝 → 폐쇄 30일 뒤 글·사진·카테고리와 함께 삭제, 블로그 행은 남기고 주소는 비움 (D-86, 002)
- 글 본문 길이와 세는 기준 → 최대 5,000자, 공백·마크다운 기호 포함, 서버에서 검사 (D-92, 004)

회원(001) 확인 질문 17개 → 추천안대로 확정 (D-97, 2026-10-07)

남은 확인 필요 항목은 각 명세의 `[NEEDS CLARIFICATION: …]`에 있습니다.
