# docs

메인블로그 프로젝트 문서입니다. 사람과 AI 에이전트가 같은 순서로 읽도록 번호를 붙였습니다.
에이전트 작업 규칙은 저장소 루트의 `CLAUDE.md`, 개발 원칙은 `.specify/memory/constitution.md`, 기능별 명세는 `specs/`에 있습니다.
소스 코드는 [b-bine-blog](https://github.com/b-bine-blog/b-bine-blog) 저장소에 따로 있습니다(D-130).
이 폴더는 명세의 근거가 되는 원본 문서를 보관합니다.

| 폴더 | 내용 | 언제 보나 |
|---|---|---|
| [01-requirements](01-requirements/) | 기본 요구사항 1~5장, 7장(구현 방식). 최신 원본(2026-10-07) + 마크다운, 이전 PDF | 기능을 만들기 전에 무엇을 해야 하는지 확인할 때 |
| [02-policies](02-policies/) | 6장 세부 정책(검색, 업로드, 태그, 중복 규칙, 글·댓글, 보안 숫자). 마크다운 + 이전 PDF | 글자 수·용량·만료 시간 같은 숫자가 필요할 때 |
| [03-decisions](03-decisions/) | 8장 결정 기록을 D-번호별 파일로 나눈 것 | 왜 그렇게 정했는지, 결정이 바뀌었는지 확인할 때 |
| [04-design](04-design/) | 여러 기능에 걸치는 설계(전체 ERD, 아키텍처). 기능별 설계는 `specs/<기능>/` | 설계를 만들거나 바꿀 때 |
| [05-plans](05-plans/) | 전체 로드맵·일정. 기능별 plan·tasks는 `specs/<기능>/` | 전체 일정을 볼 때 |
| [06-incidents](06-incidents/) | 운영 사이트에서 생긴 문제와 해결 과정 | 문제가 다시 생겼을 때 |

## 기준 문서

- 기준은 `01-requirements/요구사항분석서_원본_2026-10-07.md`(Claude Docs에서 내보낸 최신판, 결정 기록 D-92까지)입니다. 같은 폴더의 PDF(2026-10-02)는 이전 판으로 보관합니다.
- `요구사항분석서_1_기본요구사항.md`와 `02-policies/요구사항분석서_2_세부정책.md`는 최신판을 에이전트가 읽기 쉽게 표로 옮긴 것이고, 2026-10-07에 정한 D-93~D-96이 반영돼 있습니다.
- 결정을 새로 하거나 바꾸면 `03-decisions/`에 추가하고, 그 내용이 요구사항을 바꾸면 해당 마크다운도 함께 고칩니다.
