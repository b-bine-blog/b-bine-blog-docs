# 2026-10-13 메인 화면 블로그 카드가 안 보임

- 버전: v1.05 배포 직후(2026-10-13 00:20 배포, 00:24 사용자 제보)
- 영향: 메인 화면 "블로그 둘러보기"가 비고 "입력값을 다시 확인해 주세요."만 보임. 글 목록과 다른 화면은 정상
- 관련: D-115(메인 블로그 카드 5개), BLG-02, BRD-02(목록 개수 10·20·30)
- 상태: 해결(같은 날 수정본 배포)

## 무슨 일이 있었나

v1.05에서 메인 화면 블로그 둘러보기를 카드 5개로 바꾸면서, 화면이 블로그 목록 API를 `size=5`로 불렀다.
블로그 목록 API는 한 페이지 개수를 설정값 `blog.list.page-sizes`(10, 20, 30)에서만 받는다(`BlogQueryService`).
5는 목록에 없어서 서버가 400 `INVALID_INPUT`으로 거절했고, 화면은 그 오류 문구를 그대로 보여 줬다.

## 왜 배포 전에 못 잡았나

- 화면 확인을 서버 없이 했다. 블로그 목록 응답을 가짜로 꾸며 화면만 찍었는데, 그 가짜 응답은 개수 제한을 따르지 않고 무엇이든 돌려줬다.
- 전체 테스트(610개)는 서버 API를 검사한다. 메인 화면 JS가 어떤 값을 보내는지는 검사하지 않는다.

## 어떻게 고쳤나

API는 그대로 두고 화면을 고쳤다(`static/js/blog-list.js`).

- 메인 화면도 기본 개수(10개)로 요청한다.
- 받은 목록에서 앞의 5개만 카드로 그린다. 보여 줄 개수는 `index.html`의 `data-size="5"`에 둔다.

API에 5를 허용하는 방법도 있었지만, 그러면 블로그 목록 화면의 개수 선택지에도 5가 섞인다. 화면 한 곳만 다르게 보여 주면 되는 일이라 화면에서 잘랐다.

## 확인

- 10·20·30이 아니면 400을 돌려주는, 실제 서버와 같은 규칙의 가짜 서버로 메인 화면을 열어 요청이 `size=10`으로 나가고 카드가 5개 그려지는 것을 확인했다.
- 수정본 배포 뒤 서버 기동 확인이 통과했다.

## 다음에는

- 화면 확인용 가짜 응답도 실제 API의 입력 규칙(개수, 글자 수)을 따르게 만든다.
- 새로 부르는 API 값이 계약(`specs/*/contracts/*.yaml`)의 허용값 안에 있는지 배포 전에 본다.
