# D-97 회원 기능 세부 규칙 17개 확정 (001 확인 질문 추천안 채택)

- 날짜: 2026-10-07
- 관련 항목: USR-01~08, SEC-02~05, SEC-13, 4.5, 6.5, 6.7
- 상태: 확정

## 결정
문서에 값이 없던 회원 기능 세부 규칙을 아래처럼 정한다. 숫자는 설정값으로 둔다(D-68).

| 항목 | 결정 |
|---|---|
| 로그인 실패 문구 | 없는 이메일과 틀린 비밀번호를 구별하지 않고 "이메일 또는 비밀번호가 맞지 않습니다". 없는 이메일도 같은 잠금 안내 |
| 실패 횟수 초기화 | 로그인 성공, 5분 잠금 해제, 비밀번호 재설정 때 |
| 로그인 IP별 요청 제한 | 같은 IP에서 10분에 20번 |
| 사람 확인 3번 실패 기준 | 계정 기준(잠금과 같은 실패 횟수) |
| 로그인 유지 14일 | 로그인한 때부터 고정 14일 |
| 글쓰기 중 연장 요청 | 입력이 있을 때 5분마다 |
| Access Token 유효 시간 | 15분 |
| 비밀번호 변경한 기기 | 로그인 유지(새 토큰 발급), 다른 기기만 로그아웃 |
| 이메일 인증 뒤 가입 마감 | 인증을 마친 때부터 30분 |
| 비밀번호 특수문자 | 키보드 영문 특수문자 32종, 공백 제외 |
| 닉네임 대소문자 | 구분하지 않음(`Abc`와 `abc`는 중복) |
| 닉네임 예약어 | 대소문자만 바꾼 값과 예약어를 포함한 값도 막음 |
| 전화번호 형식 | 010으로 시작하는 11자리 숫자 |
| 이름 규칙 | 앞뒤 공백을 뺀 2~20자, 한글·영문·공백 |
| 가입 안 된·탈퇴한 이메일로 비밀번호 찾기 | 메일을 보내지 않음, 화면 문구는 같게 |
| 재설정 인증번호 다시 보내기 | 1분에 한 번(가입 인증과 같음) |
| 탈퇴 30일 보관 중 닉네임 | 다른 회원이 쓸 수 없고 30일 뒤부터 가능 |

## 이유
각 항목의 추천 이유는 `specs/001-member-auth/clarify-questions.md`에 있다. 가입 여부를 드러내지 않는 원칙(D-28), 재설정 시 잠금 해제(USR-06), 가입과 같은 인증 코드 재사용(D-25)에 맞췄다.
