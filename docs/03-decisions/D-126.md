# D-126 배포를 무중단(블루-그린)으로 바꾼다

- 날짜: 2026-10-13
- 관련 항목: D-106(GitHub Actions 배포), D-123(Git Flow), D-108(릴리스 노트)
- 상태: 일부 변경됨 → D-129 (graceful 종료와 nginx 설정은 그대로)

## 결정
1. 앱은 두 포트 8370(`APP_PORT`)과 8371(`APP_PORT_B`)을 번갈아 쓴다. 지금 사용자를 받는 포트는 서버의 `~/blogproject/active-port`에 적는다.
2. 배포(`deploy/deploy.sh`)는 새 앱을 쉬는 포트에 먼저 켜고, `/api/public-config`가 응답하면 `active-port`를 바꾼 뒤 옛 앱을 끈다. 새 앱이 뜨지 않으면 옛 앱을 그대로 두고 배포를 실패로 끝낸다.
3. 옛 앱은 처리 중인 요청을 끝내고 내려간다(`server.shutdown: graceful`, 최대 `APP_SHUTDOWN_TIMEOUT` 20초).
4. nginx는 두 포트를 하나의 upstream으로 두고, 연결이 안 되거나 502/503인 포트는 건너뛴다(`proxy_next_upstream`). 그래서 배포할 때마다 nginx를 reload하지 않는다. 설정 사본은 `deploy/nginx/mainttblog.java21.net.conf`.
5. 서버 nginx를 이 설정으로 한 번 바꾸고 reload한 뒤 `~/blogproject/blue-green-on` 파일을 만들어야 무중단으로 동작한다. 파일이 없으면 예전처럼 8370 하나에서 껐다 켠다(그동안 점검 중 화면). nginx가 8371을 모르는 채로 그쪽에 앱을 띄워 사이트가 내려가는 것을 막기 위해서다.
6. 릴리스 노트 워크플로는 `active-port`의 포트로 앱에 붙는다.
7. 두 앱이 잠깐 함께 도는 동안 예약 작업은 ShedLock이 한 번만 돌게 한다. 요청 횟수 제한은 앱마다 따로 센다(잠깐이라 받아들인다).

## 이유
과제 항목 "GitHub Actions 기반 CI/CD 구성(무중단)"을 진행하기로 했다(2026-10-13 사용자). 두 번째 포트 8371은 사용자가 정했다.
