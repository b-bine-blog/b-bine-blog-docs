# D-108 수정 사항은 메인 공지에 릴리스 노트로 올린다

- 날짜: 2026-10-12
- 관련 항목: BRD(메인 공지), D-106
- 상태: 확정

## 결정
화면이나 기능을 바꿔 운영 서버에 배포하면, 바뀐 부분을 캡처한 그림과 함께 메인 공지사항에 릴리스 노트를 올린다.
- 노트는 저장소 `release-notes/<날짜-이름>/notice.md`에 둔다. 첫 줄 `# v1.00 제목`처럼 버전으로 시작하고(작은 수정은 v1.01, v1.02… 순서로 올림, 2026-10-12 사용자 요청) 30자 이하(FR-003), 나머지는 마크다운 본문. 그림은 같은 폴더의 파일을 `![설명](파일.png)`로 가리킨다.
- GitHub Actions `release-note` 워크플로(직접 실행, 입력: 노트 폴더)가 노트를 서버로 보내고, 서버 안에서 `deploy/post_notice.py`가 관리자 계정으로 로그인해 공지 이미지를 올린 뒤 공지를 만든다.
- 관리자 계정은 GitHub secrets `NOTICE_ADMIN_EMAIL`, `NOTICE_ADMIN_PASSWORD`에만 둔다.
- 이미 올린 노트를 고칠 때는 폴더에 `notice-id`(공지 번호)를 두고 notice.md를 고쳐 push하면 그 공지를 수정한다.
- 노트는 배포가 끝난 뒤에 올린다(노트에 적힌 내용이 사이트에 이미 있어야 함).

## 이유
사용자가 2026-10-12에 "이제부터 릴리스 노트를 공지사항에 올리고, 수정 부분을 캡처해 이미지와 같이" 올리기로 정함.
