# D-131 블로그 채팅은 3초 폴링으로, 챗봇은 명령어 봇과 관리 봇까지

- 날짜: 2026-10-14
- 관련 항목: SOC-07(신설), D-72(알림 30초 폴링), D-129(롤링 배포, 앱 2개), 4.3(이중화), [009-blog-chat](../../specs/009-blog-chat/spec.md)
- 상태: 확정

## 결정
1. 개별 블로그에 채팅창을 두고, 화면은 3초마다 새 메시지를 묻는다(폴링). 간격은 설정값 `chat.poll-interval`(기본 3초, D-68).
2. 실시간 연결(WebSocket·SSE)은 쓰지 않는다. 메시지는 DB에 두어 앱 2개(8370·8371) 중 어디로 요청이 가도 같은 메시지를 본다.
3. 챗봇 범위는 2단계까지: 명령어 봇(블로그장이 등록한 `!명령어`에 답)과 관리 봇(금칙어·도배 막기, 새 글 알림). AI 답변 봇(3단계)은 이번에 만들지 않는다.

## 이유
- 폴링: 실시간 연결보다 느리지만 지금 앱 2개 롤링 구조에서 그대로 돌아가 더 안정적이라고 봤다(2026-10-14 사용자 결정). 실시간 연결은 앱끼리 메시지를 나눌 방법이 필요해 아직 정하지 않은 4.3 이중화와 얽힌다.
- 3초: 사용자가 3초를 생각하고 있었고, 알림의 30초는 채팅에는 너무 느리다(2026-10-14 사용자 결정).
- 범위: 사용자가 "2단계로 가자"로 명령어 봇과 관리 봇까지 골랐다(2026-10-14).
