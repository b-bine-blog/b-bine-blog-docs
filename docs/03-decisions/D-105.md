# D-105 운영 배포는 GitHub Actions가 만든 도커 이미지로

- 날짜: 2026-10-11
- 관련 항목: SCL-02, D-75
- 상태: 변경됨 → D-106

## 결정
운영 서버 배포는 GitHub Actions가 도커 이미지를 만들어 SSH로 서버에 보내고, 서버의 `deploy/deploy.sh`가 그 이미지를 실행하는 방식으로 한다.
- 워크플로: `.github/workflows/deploy.yml`. main에 push되거나 Actions 화면에서 직접 실행할 때 돈다.
- 이미지: 저장소 루트 `Dockerfile`. 이미지 저장소(레지스트리)는 쓰지 않고, 이미지 파일을 SSH로 복사한다.
- 서버 접속 정보, DB 접속 정보, 비밀 키는 GitHub Repository secrets에만 둔다. 앱 포트는 `APP_PORT` 시크릿으로 받는다(D-68).
- 업로드 이미지는 서버의 `~/blogproject/uploads`를 컨테이너에 붙여 재배포해도 남게 한다(D-75).
- nginx 뒤에서 실제 접속 IP를 쓰도록 `server.forward-headers-strategy=native`를 켠다(로그인 횟수 제한, R-06).

## 이유
수업 배포 설명서(서버 배포 설명서, 2026-10-08)가 도커 이미지 방식을 쓰고, 사용자가 2026-10-11에 이 방식으로 배포하겠다고 정함.

## 이전 내용 → 바꾼 이유
2026-10-08에 "도커 없이 jar로 배포"를 골랐으나(결정 파일은 만들지 않음) 사용자가 도커 이미지 배포로 바꿈. 로컬 개발에서 도커는 여전히 가짜 메일함(Mailpit)에만 쓴다.
