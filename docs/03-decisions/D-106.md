# D-106 운영 배포는 도커 없이 jar로

- 날짜: 2026-10-12
- 관련 항목: SCL-02, D-75, D-105
- 상태: 변경됨 → D-127

## 결정
운영 서버 배포는 도커를 쓰지 않는다. GitHub Actions가 jar(`bootJar`)를 만들어 SSH로 서버 `~/blogproject`에 보내고, 서버의 `deploy/deploy.sh`가 `java -jar`로 실행한다(서버 Java 21).
- 워크플로: `.github/workflows/deploy.yml`. main에 push되거나 Actions 화면에서 직접 실행할 때 돈다.
- 서버 접속 정보, DB 접속 정보, 비밀 키는 GitHub Repository secrets에만 둔다. 포트는 `APP_PORT`(8370) 시크릿으로 받는다(D-68).
- 이전 앱은 스크립트가 남긴 PID 파일의 프로세스만 멈춘다(여럿이 같이 쓰는 서버).
- 업로드 이미지는 `~/blogproject/uploads`에 둬 재배포해도 남게 한다(D-75). 로그는 `~/blogproject/app.log`.
- nginx 뒤에서 실제 접속 IP를 쓰도록 `server.forward-headers-strategy=native`를 켠다(로그인 횟수 제한, R-06).

## 이유
사용자가 2026-10-12에 "도커는 사용하지 마"라고 정함. 로컬 개발에서도 도커는 가짜 메일함(Mailpit)에만 쓴다.

## 이전 내용 → 바꾼 이유
D-105 "도커 이미지로 배포" → 사용자가 도커를 쓰지 않기로 바꿈. 도커 이미지로는 한 번도 서버에 배포하지 않았다(첫 실행은 이미지 빌드 중 취소).
